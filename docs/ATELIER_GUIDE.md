# 의뢰 공방 — 지금 어디까지 만들었나

> 이 문서는 **현황과 운영**이다. "무엇이 되고, 무엇이 안 되고, 의뢰가 오면 내가 뭘 하면 되는가."
> 코드 수준의 구현 기록과 밟은 함정들은 **[COMMISSION_ATELIER.md](./COMMISSION_ATELIER.md)** 에 따로 있다.

마지막 갱신: 2026-08-21 (심화 문답) · 1~3단계 구현은 2026-08-17 완료

## 한 줄로

**마을 지하에 숨겨진 홈페이지 제작 의뢰 창구.** 방문자가 AI 접수원과 대화하며 요구사항을
정리하고 참고 견적을 받아 의뢰를 넣으면, 내가 승인한 뒤 직군별 AI 에이전트 넷이
실제 산출물(기획서·디자인 가이드·HTML 시안·API 명세)을 만든다.

| 단계 | 내용                                 | 상태                  |
| ---- | ------------------------------------ | --------------------- |
| 1    | 접수·상담·견적 + 관리자 접수함       | ✅ 완료               |
| 2    | 지하 3D 공방 + 팀 NPC 5명            | ✅ 완료 (에셋은 임시) |
| 3    | 직군별 에이전트가 실제 산출물 제작   | ✅ 완료               |
| 4    | 접수 뒤 심화 문답으로 제작 정보 회수 | ✅ 완료               |

**포트폴리오의 다른 구역과 성격이 다르다.** 나머지는 전부 *내가 입력 → 마을에 반영*인데,
공방만 방향이 반대다: **외부인이 입력 → 내가 처리**. 마을에서 유일하게 바깥 사람이
데이터를 쓰는 곳이고, 그래서 스팸 방어·개인정보·금액 분쟁이 전부 여기서만 문제가 된다.

## 1. 왜 이렇게 만들었나 — 결정 다섯 개

### ① 숨기면서 동시에 잘 보이게 (진입을 둘로 갈랐다)

컨셉은 "숨겨진 공간"인데 목적은 "실제로 의뢰를 받는 창구"다. **이 둘은 정반대 방향이다.**
진짜 의뢰를 받겠다면서 아무도 못 찾으면 창구로서 실패한다.

그래서 입구를 성격별로 나눴다.

| 경로                         | 도착지               | 성격                            |
| ---------------------------- | -------------------- | ------------------------------- |
| 우하단 **🛠️ 제작 의뢰** 버튼 | 접수 데스크(2D) 직행 | **실사용.** 마찰 0, 모바일 포함 |
| 광장 우물 옆 **지하 해치**   | 3D 공방              | 발견의 재미                     |
| **포스트**(연락 NPC)의 귀띔  | 3D 공방              | 발견의 재미                     |
| 공방 안 **도안** 클릭        | 같은 접수 데스크     | 두 경로가 여기서 만난다         |

숨김은 *유일한 입구*가 아니라 *멋있는 두 번째 입구*다.

> 처음엔 해치에 표지를 안 뒀다가 **만든 사람도 못 찾는 입구**가 됐다.
> 지금은 옆에 나무 팻말(`의뢰 공방 / 지하 ↓`)이 서 있다.

### ② 금액은 AI에게 맡기되 규칙으로 가둔다

AI가 부른 금액은 분쟁 소지다. 그래서 규칙 기반 기준선을 먼저 계산하고
(유형별 기준 + 결제·로그인 같은 무거운 기능 가산), **모델의 답을 그 기준선의
0.6~1.8배 안으로 clamp** 한다. 맥락을 반영한 조정은 허용하되 0원이나 1억은 구조적으로 막힌다.

금액이 나가는 모든 자리(화면·디스코드 알림)에 면책 문구가 붙는다.

### ③ AI가 죽어도 접수는 살아야 한다

`OPENAI_API_KEY`가 없거나 호출이 실패하면 **규칙 기반 상담으로 조용히 내려간다.**
말투는 밋밋해지지만 접수는 끝까지 된다. 창구가 멈추는 게 제일 나쁘다.

### ④ 에이전트에게 진행 권한을 주지 않는다

내가 처음에 못 박은 요구가 _"에이전트가 만들되 언제까지나 나랑 상의한다"_ 였다.
이건 프롬프트로 부탁할 일이 아니다 — 언젠가는 안 지킨다.

**그래서 진행 권한 자체를 코드가 쥔다.** 에이전트가 할 수 있는 일은 작업을
`검수 대기`까지 옮기는 것뿐이고, 거기서 앞으로 나가는 함수는 하나뿐이며
그 함수가 자동으로 불리는 경로는 코드에 없다.

승인 규칙을 **행의 존재**로도 표현했다 — 디자인·프론트·백엔드의 작업 행은
브리프를 승인해야 비로소 만들어진다. 승인 전에는 돌릴 작업 자체가 없다.

### ⑤ 남의 일감은 내 리포에 안 들어온다

에이전트 산출물은 `workspace/commissions/<접수번호>/` 안에만 생긴다.
`.gitignore`에 들어 있어 포트폴리오 리포에 커밋되지 않고,
경로 검사가 그 폴더 밖으로 나가는 파일 접근을 전부 막는다(읽기까지).

## 2. 지금 되는 것

### 손님 시점

1. 마을 우하단 **🛠️ 제작 의뢰** 버튼 → 접수 데스크가 바로 열린다 (모바일 포함)
2. 접수원 **도안**과 대화 → 사이트 유형·페이지·기능·톤·일정·예산을 하나씩 정리해준다
3. 어느 정도 모이면 **참고 견적 범위**와 면책 문구가 뜨고 접수 폼이 열린다
4. 제출하면 접수번호 `WO-XXXXXXXX` 와 **심화 문답 링크**를 받는다
5. 그 링크로 들어오면 도안이 제작에 필요한 것들을 하나씩 더 묻는다 (§2-1)

스팸 방어: 허니팟 필드 + 동의 체크 + 레이트리밋(시도 20회/시간, **성공** 3건/시간, 전체 40건/일).
시도와 성공을 따로 세는 이유는 이메일 오타 두어 번에 멀쩡한 손님이 한 시간 잠기는 일이 실제로 났기 때문이다.

### 2-1. 심화 문답 — 접수는 낚싯바늘이고, 정보는 그다음에 받는다

**이 창구의 목적은 좋은 산출물을 뽑는 게 아니라, 내가 잘 만들 수 있게 정보를 받아내는 것이다.**
그런데 1차 상담은 견적을 내려고 만들어져 있었다. `CommissionDraft` 13개 필드 중 5개가
견적 전용이었고, 도안이 쫓는 항목도 유형·요약·페이지·기능·일정 다섯뿐이었다.

정작 만들 때 필요한 건 그게 아니다. **만든 뒤 누가 고치는지**(정적/CMS/어드민을 가른다),
**사진과 글을 누가 준비하는지**(지연 원인 1위), **뭐가 달라져야 성공인지**(카피와 CTA가 여기서 나온다),
**이미 가진 게 있는지**. 이걸 안 물어보니 체리가 산출물에 "확인 필요" 로 적어 놓았고,
결국 내가 손님에게 다시 연락해야 했다 — 공방이 없애려던 왕복이 그대로 남았던 것이다.

**그렇다고 1차에서 캐물으면 안 된다.** 접수 문턱을 낮춘 건 옳은 결정이었다
(`ready_to_submit` 은 유형 + (페이지 또는 기능) 만 본다). 여덟 가지를 캐물으면 접수까지
오지 못하고 떠난다. 그래서 **뽑는 시점을 접수 뒤로 옮겼다.**

|           | 1차 (접수 창구)                  | 2차 (심화 문답)                                       |
| --------- | -------------------------------- | ----------------------------------------------------- |
| 목적      | 얼마짜리 일인가                  | 어떻게 만들어야 잘 만드는가                           |
| 문턱      | 낮게. 두 항목이면 접수 열림      | 높여도 안전 — **이미 접수한 사람은 이탈 비용이 낮다** |
| 제작 슬롯 | 들리면 담되 **먼저 묻지 않는다** | `depth_missing` 을 하나씩 쫓는다                      |
| 화면      | `CommissionDesk mode="intake"`   | 같은 컴포넌트 `mode="depth"`                          |

받는 항목 일곱 개는 `commission_service._DEPTH_SLOTS` 한 곳에 표로 있다(라벨·필수 여부·질문 문구).
앞의 넷이 필수, 뒤의 셋(피하고 싶은 것 / 참고 사이트의 이유 / 결정하는 분)은 있으면 좋은 것이다.

**열쇠는 접수번호가 아니라 `access_token` 이다.** `WO-XXXXXXXX` 는 8 hex 라 사람이 받아적을 수
있는 대신 열거를 시도할 수 있어서 조회 키로 쓰지 않는다. 그리고 이 화면은 **연락처를 절대
내려보내지 않는다** — 링크가 메일·메신저 어디로 전달될지 통제할 수 없기 때문이다.

링크가 손님에게 닿는 자리는 셋: **접수 완료 화면**(가장 잘 눌린다 — 이미 마음을 낸 참이라),
**디스코드 알림**, **`/admin` 상세의 [링크 복사]**(회신 메일에 붙여 쓴다).

> ### 실제로 돌려 보고 잡은 것 셋
>
> 브라우저로 2턴 태워 보고서야 드러났다. 전부 `tests/test_commission_depth.py` 가 잡는다.
>
> 1. **요약이 원문을 덮어썼다.** 손님이 "가격표가 자주 바뀌어서 직접 고치고 싶어요,

>    정작 `_DEPTH_QUESTIONS` 에 `**강조**` 를 넣어 두어서, 손님 화면에 별표가 그대로 보였다.
>    말풍선은 평문 렌더다.

### 내 시점

- 접수되면 **디스코드로 알림**이 온다 (웹훅 설정 시)
- `/admin` → **의뢰 접수함**에서 접수 내용 + 손님과 도안이 나눈 **상담 대화 전문**을 본다
- 같은 화면에서 게이트를 통과시키고, 직군별 작업 상태·비용·산출물을 검수한다
- HTML 시안은 관리자 페이지 안에서 바로 미리보기 (스크립트·외부 요청이 차단된 샌드박스)

| NPC      | 직군       | 하는 일                              |
| -------- | ---------- | ------------------------------------ |
| **도안** | 접수원     | 상담·견적·접수. 클릭하면 접수 데스크 |
| **체리** | 기획       | 요구사항 정리서                      |

마을에서 말을 걸면 각자 다른 성격으로 답하고, **자기가 지금 맡은 의뢰의 진행 상황**을 말한다

NPC끼리 마주치면 티격태격한다 (프론트↔백엔드: _"그건 백엔드에서 주셔야죠"_).

## 3. 의뢰가 오면 내가 하는 일

```
접수 도착 (디스코드 알림)
   ↓
/admin → 의뢰 접수함 → 상세
   ↓
[게이트 1] 접수 승인          ← 이 의뢰를 받을지 결정
   ↓
체리 실행                     npm run atelier -- WO-XXXXXXXX planner
   ↓
요구사항 정리서 읽기
   ↓
[게이트 2] 브리프 승인        ← 승인한 내용이 팀 3명에게 그대로 넘어간다
   ↓                            (마음에 안 들면 피드백 적고 반려 → 체리가 다시)
먹지·리코·굴뚝 실행           npm run atelier -- WO-XXXXXXXX
   ↓
산출물 검수 (HTML 시안은 화면에서 바로 확인)
   ↓
[게이트 3] 전달 완료          ← 실제 전달(메일 등)은 내가 직접
```

**각 게이트에서 반드시 멈춘다.** 자동으로 끝까지 가지 않는다.
반려할 때 적은 피드백은 다음 실행 프롬프트에 그대로 들어간다.

### 실행 두 가지 방법

| 방법                            | 조건                                            |
| ------------------------------- | ----------------------------------------------- |
| `/admin` 의 [실행] 버튼         | `AGENT_WORKER_ENABLED=true` 일 때만 (기본 꺼짐) |
| `npm run atelier -- <접수번호>` | 항상                                            |

둘 다 같은 함수를 부르고 게이트도 똑같이 걸린다. 터미널이라고 승인을 건너뛰는 뒷문은 없다.

기본을 꺼 둔 이유: 공개 배포된 웹 서버 프로세스에서 파일 쓰는 에이전트가 돌면 안 된다.
배포본은 **승인만 웹에서 하고 실행은 내 컴퓨터에서** 한다.

### 유용한 명령

```bash
npm run atelier                              # 접수 목록과 상태
npm run atelier -- WO-XXXXXXXX               # 대기 중인 작업 전부
npm run atelier -- WO-XXXXXXXX planner       # 한 직군만
```

> `--role planner` 는 **npm이 가로챈다.** 직군은 위치 인자로 넘긴다.

## 4. 산출물이 어떻게 나오나

```
workspace/commissions/WO-31960672/
├─ 01-기획/요구사항-정리서.md
├─ 02-디자인/디자인-가이드.md

│           /화면-명세.md
└─ 04-백엔드/API-명세.md, DB-스키마.md
```

### 실측 (동네 베이커리 소개 사이트 한 건)

| 직군         | 시간    | 비용        |
| ------------ | ------- | ----------- |
| 체리(기획)   | 49초    | $0.13       |
| 먹지(디자인) | 68초    | $0.18       |
| 리코(프론트) | 176초   | $0.46       |
| 굴뚝(백엔드) | 138초   | $0.32       |
| **합계**     | **8분** | **약 $1.1** |

프롬프트에 박아 둔 제약이 실제로 지켜졌다:

- 손님의 이름·이메일·전화번호를 산출물에 옮기지 않는다 (문서가 나중에 남의 손에 갈 수 있다)
- 확정 견적·확정 납기를 약속하지 않는다
- 모르는 건 지어내지 않고 **"확인 필요"** 항목으로 남긴다
- HTML 시안은 외부 요청 0건의 자립형 단일 파일 (CDN·웹폰트·외부 이미지 금지)

체리는 시키지도 않았는데 **손님 예산(150만원)과 참고 견적 하단(190만원)이 어긋난다**는 걸
스스로 짚고 착수 전 조정이 필요하다고 적었다.

## 5. 아직 안 되는 것

### ⚠️ 배포 전 필수 (지금 안 되어 있음)

- [ ] **`ADMIN_PASSWORD` 설정** — 비어 있으면 `/admin` 인증이 **꺼진다.**
      공방이 생긴 뒤로는 그게 새면 포트폴리오가 아니라 **방문자의 이름·이메일·전화번호와
      의뢰 산출물**이 샌다. 이게 제일 급하다.
- [x] ~~`ADMIN_SECRET` 기본값 방치~~ → **코드가 막는다.** 비밀번호를 걸어 뒀는데 서명키가
      예시 기본값이면 `security.assert_secret_usable()` 이 인증을 통과시키지 않는다(500).
      비밀번호만 바꾸고 서명키를 두는 실수가 제일 흔하고, 그때 겉보기엔 로그인이 정상
      동작해서 뚫린 줄을 모르기 때문이다. **단, 값 교체는 여전히 사람이 해야 한다** —
      안 하면 `/admin` 이 아예 안 열린다.
- [ ] `DISCORD_WEBHOOK_URL` 설정 — 없으면 `/admin` 을 열기 전까지 새 의뢰를 모른다
- [ ] SQLite 백업 또는 Postgres 전환 — 접수 데이터는 날아가면 안 된다

상세한 파일 지도와 함정은 [COMMISSION_ATELIER.md](./COMMISSION_ATELIER.md) 에 있다. 요약만:

| 3D 공방 씬                   | `src/components/interior/AtelierInterior.tsx`       |
| 해치·팻말 위치               | `src/components/village/AtelierHatch.tsx`           |

### 손대기 전에 알아야 할 것 셋

1. **게이트 규칙은 `gate.py` 한 곳에만 있다.** 서비스는 그 결정을 저장만 한다.
   여기 손대면 `backend/tests/test_commission_gates.py` 가 잡는다 (테스트 140개).
2. **에이전트 권한 설정은 한 세트다.** `permission_mode="default"` + `allowed_tools=()`
   - `setting_sources=[]` — 편하자고 하나만 바꾸면 경로 검사가 **에러 없이 조용히** 죽는다.
3. **NPC id 부분 매칭 순서.** `atelier-backend` 가 `"backend"` 검사에 먹혀 일반 개발자
   NPC로 잡히는 함정이 있다. 공방 분기가 항상 맨 앞이어야 한다.
