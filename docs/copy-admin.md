# 관리자 페이지 (`/admin`): 마을 배전반 2.0

> 오늘의 기록이 마을을 바꿉니다

- **경로:** `http://localhost:3000/admin` (셸은 `src/app/admin/page.tsx`, 화면은 `src/app/admin/_screens/*`)
- **성격:** 방문자용이 아닌 **본인 전용 기록 앱**입니다. 휴대폰에서 매일 쓰는 것을 기준으로 만들었습니다(2026-10-17 개편, 10-18 한 화면으로).
- **연결 대상:** FastAPI 백엔드 (`NEXT_PUBLIC_API_BASE_URL`, 기본 `http://localhost:8000`)
- **한 줄 요약:** 계획(작업 지시서)과 하루 기록 → `daily_activity` → `village_service.derive_village_state` → 마을 조명·NPC 상태·장식

---

## 00. 들어오기: 금고 문

1. 진입 시 `GET /admin/auth-status` 로 인증 사용 여부(`auth_enabled`)를 확인합니다.
2. 인증이 켜져 있으면 **토큰이 있어도** 금고 문(`_components/AdminGate.tsx`)이 먼저 뜹니다. 토큰은 서명값이라 비밀번호를 바꿔도 7일간 살아 있기 때문입니다. 토큰을 지우지는 않습니다(갓생 섬이 같은 토큰을 씁니다).
3. 다이얼 네 칸을 눌러 돌리거나, 아래 입력칸에 번호를 직접 치고(휴대폰 숫자 키보드) 레버를 당기면 `POST /admin/login` 으로 확인합니다. 정답은 서버만 압니다.
4. 백엔드가 응답하지 않으면 잠금 없이 통과합니다. 로컬 개발 편의이고, 실제 실패는 송전 때 드러납니다.
5. 휴대폰 폭(480px 이하)에서는 다이얼과 레버가 작아집니다.

```

               ☐ 하체 루틴 40분
```

- 탭이 없습니다. 2026-10-17 의 탭 넷(배전반·지시서·기록실·서랍)은 손잡이가 많고, 지시서를 끝내도 다른 탭에 있는 게이지가 차는 걸 못 봐서 하루 만에 접었습니다.
- 지도는 스크롤해도 위에 붙어 있어, 게이지를 밀면 그 자리에서 건물이 켜지는 게 보입니다. 목표선을 넘기면 짝 건물에 조준 고리가 잠깐 걸립니다.
- 루미 얼굴은 `previewNpcMoods` 의 `guide-npc` 기분을 표정 넷(졸림·차분·신남·뿌듯)으로 그립니다. 기분이 바뀌면 한 번 커지고, 누르면 한 줄이 말풍선으로 뜹니다. 새 규칙은 없습니다.
- 더보기(⋯): 기록실 · 서랍장 · GitHub 커밋 동기화 · 어제 기록 복사 · 마을 보기 · 배전반 잠그기. 기록실과 서랍장은 전체 화면으로 열리고 "← 배전반"으로 돌아옵니다. 새로고침하면 배전반으로 돌아옵니다(마지막 화면을 기억하지 않습니다).
- 내 처리를 기다리는 의뢰가 있으면 맨 위에 띠가 뜨고, 칩을 누르면 서랍장의 의뢰 접수함이 열립니다.
- 넓은 화면에서도 한 열(최대 560px)입니다. 두 단으로 가르지 않습니다.

## 02. 회로 블록 (`_components/CircuitBlock.tsx`)

| 부분        | 동작                                                                                                                                                                                  |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 머리        | 이름 · 설명 · 분 · "상세"(접힌 부속 입력)                                                                                                                                             |
| 게이지      | **유일한 손잡이.** 값 0 에서 탭하면 목표치, 켜져 있으면 탭마다 +15, 끌면 그 위치, 600ms 길게 누르면 0. 방향키 ±5, Delete 로 0. 세로선이 목표, 끝은 목표의 3배, 목표를 넘은 칸은 금색. |
| 지시서 목록 | 그 회로에 건 지시서. 오른쪽으로 밀면 완료, 누르면 고치기.                                                                                                                             |
| 한 줄 추가  | 제목을 치고 Enter. 입력칸에 들어가면 분량 칩(15·30·45·60·90, 기본 30)과 마감 꼬리표가 펼쳐집니다.                                                                                     |

| 회로      | 목표          | 상세 안           | 마을에서 켜는 곳             |
| --------- | ------------- | ----------------- | ---------------------------- |
| 운동      | 30분          | 운동 종류 태그    | 중앙 광장 · 루미             |
| 공부      | 60분          | 주제 입력 + 태그  | 기술 건물 다섯 채            |
| 코딩      | 120분         | 커밋 ±1 · 레포 칩 | 광장, 레포가 겹치는 프로젝트 |
| 프로젝트  | 60분          | (없음)            | 그 프로젝트 건물             |
| 회로 없음 | (게이지 없음) | (없음)            | 완료하면 +10kWh 만           |

- 목표선을 **손으로** 넘기는 순간만 불꽃, "목표 달성 +50kWh"(프로젝트는 "목표 달성"), 지도 건물 번쩍, 화음이 납니다. 불러오기나 지시서 완료로 넘어갈 때는 축하하지 않습니다.
- 프로젝트 회로는 분이 있거나 지시서가 있는 것만 보입니다. "+ 프로젝트 회로 켜기"로 고르면 목표치(60)로 켜집니다.
- 컨디션 줄: 기분 버튼 4개(차분함·집중됨·피곤함·뿌듯함), 집중도 다이얼(48px, 끌거나 방향키), 오늘 한 줄.

## 03. 작업 지시서 (`_components/OrderRow.tsx`, `_lib/usePlanItems.ts`)

그날의 계획입니다. 지시서는 회로 블록 안에 살고, **회로와 걸어 둔 분량**이 있습니다.

- **완료**: 오른쪽으로 80px 밀거나 Enter/Space. 카드에 "완료" 도장이 찍히고, 퓨즈에서 전기 한 방울이 **위 게이지까지 날아가 닿는 순간** 분이 더해지며 게이지가 번쩍입니다(`fx.bolt`). 서버 요청(`PUT /admin/plan-items/{id}`)은 밀자마자 보냅니다(낙관적). 실패하면 되돌립니다.
- **완료 취소**: 다시 밀거나 Enter. 더했던 만큼 뺍니다.
- **고치기**: 카드를 누르면 분량 칩 · 내일로 · 지우기가 펼쳐집니다. 완료된 지시서의 분량은 서버가 409 로 막습니다(먼저 되돌려야 합니다).
- **내일로**: 아래 "내일로 넘긴 것"에 모입니다. 거기서 오른쪽으로 밀면 오늘로 돌아옵니다.
- **지우기**: 완료된 지시서를 지워도 그날 기록에 더한 분량은 남습니다.
- 왼쪽 밀기 같은 숨은 제스처는 없습니다.

## 04. 송전 (저장)

- 맨 아래 ⚡ 버튼을 **0.9초 꾹 누르면** 고리가 차고 송전됩니다. 일찍 떼면 "조금 더 꾹 눌러 주세요". 하루 전체를 덮어쓰는 동작이라 스쳐서 일어나면 안 되기 때문입니다. 키보드는 Enter·Space 로 바로 됩니다.
- 켜진 회로도 바뀐 것도 없으면 "켜진 회로가 없어요".

```
[송전]
  → POST /activity   (normalizeForm: 중복 태그 제거 · 0분 프로젝트 제거)
  → GET /activity/history?days=140  +  GET /village-state
  → 오늘이면 송전 결과 화면, 지난 날이면 토스트
```

### 송전 결과 화면 (`_components/RewardOverlay.tsx`)

방금 송전한 기록의 지도 → 이번에 들어간 kWh 가 0부터 차오름 → 등급이 올랐으면 "등급 상승" 배지 → 마을 요약 → 밝아진 건물(광장 제외 상위 6) · 새 장식 · 루미의 한마디가 하나씩 올라옵니다. 목록은 **서버가 돌려준 마을 상태**에서 옵니다.

### 장식 해금 조건 (`village_service.py`)

| 해금                               | 조건                                 |
| ---------------------------------- | ------------------------------------ |
| 운동 동상 (`training-statue`)      | 운동 완료                            |
| 연구소 등대 (`lab-beacon`)         | GitHub 커밋 5개 이상                 |

## 05. 전력(kWh)과 등급 (`_lib/power.ts`)

**저장하는 값이 아니라 기록에서 매번 다시 계산하는 값**입니다. 따로 쌓으면 기록을 고쳐도 점수가 남아 둘이 어긋납니다.

```
하루 kWh = 운동분(운동 완료일 때) + 공부분 + 코딩분 + 프로젝트분 × 0.8 + 커밋 × 5
         + 목표 고리(운동 30 · 공부 60 · 코딩 120) 하나 채울 때마다 50
등급 문턱 = 0 · 300 · 800 · 1500 · 2500 · 4000 · 6000 · 8500 · 11500 · 15000 · …
```

- 머리의 "송전 대기"는 **지금 폼이 저장된 그날 기록보다 더 켜진 만큼**입니다. 누적 kWh 와 등급은 기록실 맨 위에 있습니다.

| 칸                | 내용                                                                 |

- 달력 칸을 누르면 그날 요약이 뜨고, **이 날 열기**를 눌러야 배전반이 그날로 바뀝니다. 스크롤하다 칸을 스쳐 편집 중인 폼이 바뀌는 일을 막기 위해서입니다.

연속 기록·달력 농도 기준:

```
raw = 공부분/3 + 코딩분/3 + 커밋수×8 + (운동 여부 ? 20 : 0) + 프로젝트분/5
level = 0(raw 0) · 1(<20) · 2(<45) · 3(<80) · 4(80+)
```

## 08. 설치형 앱(PWA)으로 쓰기

`/admin` 에서만 `public/admin.webmanifest` 가 걸립니다(`src/app/admin/layout.tsx`). 착륙장이나 마을에서는 설치 버튼이 뜨지 않습니다.

- **PC 크롬:** 주소창 오른쪽의 설치 아이콘(모니터에 화살표) → "설치". 바탕화면과 시작 메뉴에 "마을 배전반"이 생기고, 열면 주소창 없이 앱 창으로 뜹니다.
- **안드로이드 크롬:** 메뉴 → "홈 화면에 추가" 또는 "앱 설치".
- **iPhone 사파리:** 공유 → "홈 화면에 추가". 아이콘은 `apple-touch-icon.png` 를 씁니다.
- 서비스 워커는 없어서 **오프라인에서는 열리지 않습니다.** 저장이 백엔드로 가야 하는 도구라 오프라인 셸만으로는 할 수 있는 게 없기 때문입니다.
- `robots.txt` 와 layout 의 `noindex` 로 검색에서 뺍니다. 실제 방어선은 금고 문(토큰)입니다.

## 09. 손맛: 효과음 · 진동 · 불꽃

- 효과음은 파일 없이 WebAudio 로 합성합니다(`_lib/sfx.ts`): 눈금 틱, 레버 철컥, 통전, 목표 달성 화음, 퓨즈, 송전 충전음, 송전 완료 화음. 계기판의 스피커 버튼으로 끄고, 이 기기에 기억합니다.
- 진동은 지원하는 휴대폰에서만 울립니다. 화면을 한 번도 만지기 전에는 부르지 않습니다.
- 불꽃·떠오르는 글자(`_lib/fx.ts`)는 **조작한 그 순간에만** 한 번 튑니다. 상시 도는 인터벌이 없고, 모션 줄이기 설정이면 모두 꺼집니다.

## 10. 사용하는 API 한눈에

| 목적             | 엔드포인트                                                         |
| ---------------- | ------------------------------------------------------------------ |
| 인증 여부        | `GET /admin/auth-status`                                           |
| 로그인           | `POST /admin/login`                                                |
| 활동 저장        | `POST /activity`                                                   |
| 활동 이력(140일) | `GET /activity/history?days=140`                                   |
| 마을 상태        | `GET /village-state`                                               |
| AI 사용량        | `GET /admin/overview`                                              |
| GitHub 동기화    | `POST /github/sync`                                                |
| 작업 지시서      | `GET·POST /admin/plan-items` · `PUT·DELETE /admin/plan-items/{id}` |
| 코딩테스트       | `GET /coding-tests` · `POST·PUT·DELETE /admin/coding-tests`        |
| CS 노트          | `GET /cs-notes` · `POST·PUT·DELETE /admin/cs-notes`                |

작업 지시서 규칙(`backend/app/services/plan_service.py`, `tests/test_plan_items.py` 가 잠급니다):

- 완료로 바뀔 때만 그날 기록의 그 칸에 분량을 더하고, 취소하면 뺍니다. 같은 상태로 다시 보내면 아무것도 바꾸지 않습니다.
- `upsert_activity` 는 쓰지 않습니다. 하루를 통째로 덮어써 메모·커밋이 날아가기 때문입니다. 섬 기록(`quest_service`)과 같은 한 칸 갱신입니다.
- 운동 지시서는 `workout_done` 도 켭니다. 마을 점수는 이게 꺼져 있으면 운동 분을 세지 않습니다.
- 완료된 지시서의 날짜·회로·분량은 바꿀 수 없습니다(409). 먼저 완료를 취소합니다.

## 11. 이 페이지의 설계 의도 (포트폴리오 서술용)

- **계획을 끝내면 기록이 된다.** 작업 지시서를 완료하면 그 분량이 그날 기록에 들어갑니다. 같은 일을 계획표와 기록표에 두 번 적지 않게 했습니다.
- **입력을 콘텐츠로 바꾸는 파이프라인.** 한 번의 송전이 건물 조명 점수, NPC 무드, 장식 해금, NPC 대화 컨텍스트를 한 번에 갱신합니다.
- **저장 전에 결과를 보여 준다.** 게이지가 차오르고, 지도에 불이 켜지고, 전력 막대에 송전 대기가 빗금으로 쌓입니다. 저장하지 않은 상태를 경고문 대신 막대 모양으로 알립니다.
- **점수는 계산값이다.** kWh 와 등급은 기록에서 매번 다시 셉니다. 기록을 고치면 점수도 같이 맞습니다.
- **부가 정보 실패는 화면을 막지 않는다.** AI 사용량·의뢰 알림 조회가 실패해도 조용히 접고, 지시서 저장이 실패하면 화면을 되돌린 뒤 이유를 띄웁니다.
