myPortfolio 해부도

3D 마을로 걸어 다니는 포트폴리오. 이 문서는 그 마을이 실제로 어떻게 만들어져 있는지를, 폴더 이름이 아니라 소스를 열어서 정리한 것입니다. 잘 된 곳과 깨진 곳을 같은 기준으로 적었습니다.

근거 약속: 모든 구조적 주장에 파일:줄번호가 붙습니다. 문서가 거짓말을 하는지 직접 확인할 수 있어야 합니다.

git 추적 파일만 셌습니다(git ls-files). node_modules · .next · backend.venv 는 제외. 라우트는 backend/app/main.py 의 @app.* 데코레이터, 테이블은 __tablename__, 테스트는 def test_ 개수입니다.

00 — 이력

이 저장소에는 프로젝트가 둘 있습니다

커밋 783개가 2019년 10월부터 쌓여 있는데, 월별로 세어 보면 가운데가 비어 있습니다. 2024년 10월부터 2025년 12월까지 커밋이 한 개도 없습니다.

앞쪽 절반(2019~2024, 약 450커밋)은 Create React App 으로 만든 옛 포트폴리오입니다. 지금도 src/App.js · src/containers/ 로 남아 있지만 Next.js 빌드 대상이 아닙니다. 뒤쪽(2026-01, 2026-06~09)이 지금 돌아가는 마을입니다.

이 사실이 중요한 이유는 품질 편차를 설명하기 때문입니다. 2026년 8월 한 달에만 123커밋이 들어갔습니다. 마을 작업 전체의 약 39%가 한 달에 몰렸습니다. 같은 사람이 다른 속도로 쓴 코드가 한 저장소에 섞여 있고, 뒤에 나올 {{sFIND}}장의 문제들은 대부분 그 속도 구간에서 나왔습니다. 게으름이 아니라 속도의 흔적입니다.

읽는 법

막대의 절대 높이보다 모양을 보세요. 2019~2020 의 완만한 언덕은 학습용 프로젝트의 리듬이고, 2026-08 의 절벽은 마감을 향해 달린 구간입니다. 절벽 구간의 코드는 빠르게 읽고 넘어가지 말고, 뒤의 결함 장과 함께 보면 어디를 먼저 손볼지가 보입니다.

00 — 실행 단위

하나가 아니라 셋이 돕니다

"사이트 하나"로 보이지만 실제로는 독립된 프로그램 세 개입니다. 디버깅은 거의 항상 "셋 중 어느 것이 안 떴나"에서 시작하므로, 이걸 먼저 구분할 수 있어야 합니다.

1 · Next.js (프론트)

npm run dev → 3000번. 화면 전부와 3D 마을. package.json 의 dev / build / start.

2 · FastAPI (백엔드)

npm run backend:dev → 8000번. 라우트 65개와 DB. backend/app/main.py.

3 · 공방 에이전트 워커

npm run atelier. 웹 서버와 일부러 분리된 별도 프로세스입니다. scripts/atelier-worker.mjs.

세 번째가 왜 분리돼 있는지가 설계의 핵심입니다. 에이전트는 파일을 씁니다. 공개 배포된 웹 서버 안에서 파일을 쓰는 프로세스가 돌면 안 되므로, 그 경로는 기본으로 꺼져 있습니다.

직접 확인

backend/app/config.py:44 의 agent_worker_enabled: bool = False. 기본값이 False 입니다. 켜야만 웹 프로세스 안에서 에이전트가 돕니다.

00 — 알고리즘

오늘의 활동이 불빛이 되는 공식

이 제품의 약속은 한 문장입니다. 관리자가 적은 오늘의 활동이 마을의 밝기로 바뀐다. 그 변환을 실제로 하는 것은 순수 함수 하나입니다 — backend/app/services/village_service.py:69 의 derive_village_state.

아래 계산기는 그 함수를 그대로 옮긴 것입니다. 근사치가 아니라 같은 식이고, 파이썬의 //(내림 나눗셈)까지 맞췄습니다. 값을 움직여서 어떤 입력이 밝기를 지배하는지 직접 보세요.

가중치가 곧 설계 결정입니다

최종 점수는 여섯 조각의 합인데 조각마다 나누는 수가 다릅니다. 커밋과 공부는 반으로 깎이고, 운동은 3분의 1, 집중도는 4분의 1만 들어갑니다. 코딩 시간만 깎이지 않고 그대로 들어갑니다.

그리고 메모는 내용과 무관하게 한 글자만 있으면 35점입니다. 공부 시간으로 35점을 받으려면 140분이 필요합니다. 메모 한 줄 = 공부 2시간 20분이라는 뜻입니다. 의도한 것이라면 "기록하는 습관"에 준 가산점이고, 의도하지 않았다면 {{sFIND}}장의 F-02 가 그 결과입니다.

직접 해 보세요

계산기에서 커밋 3 · 공부 30분 · 주제 1 · 코딩 60분 · 집중 50 · 메모 있음을 넣어 보세요. 대단할 것 없는 하루인데 100점 · bright 가 나옵니다. 상한이 100이라 그 위로는 아무리 일해도 화면이 똑같습니다.

문제

HTTP 는 당신을 기억하지 못합니다. 요청 하나하나가 완전한 남남입니다. 방금 비밀번호를 맞혔어도 다음 요청은 그 사실을 모릅니다.

그래서

토큰이 생겼습니다. 로그인에 성공하면 "이 사람 확인됨"이라는 쪽지를 주고, 이후 요청마다 그 쪽지를 같이 보냅니다. 이 프로젝트는 X-Admin-Token 헤더에 담습니다.

그런데

쪽지는 손님이 고칠 수 있습니다. 브라우저에 저장된 값이라 사용자가 직접 바꿔 쓸 수 있습니다. "만료: 2099년"이라고 적어 보내면요?

그래서

서명이 생겼습니다. 서버만 아는 비밀키로 쪽지에 도장을 찍습니다(HMAC-SHA256). 내용을 한 글자라도 고치면 도장이 안 맞습니다. backend/app/security.py:59

그런데

비밀키가 공개돼 있다면? 도장을 아무나 찍을 수 있습니다. 비밀번호를 걸어 둔 의미가 사라집니다. 그리고 이건 겉보기에 정상 동작합니다 — 로그인도 되고 화면도 열립니다.

그래서

이 프로젝트는 그걸 막아 둡니다. 비밀번호는 걸었는데 서명키가 예시 기본값이면 인증을 아예 통과시키지 않습니다. backend/app/security.py:40 의 assert_secret_usable. 잘 만든 부분입니다.

그런데 문 하나가 덜 잠겨 있습니다

위의 방어는 전부 비밀번호가 설정돼 있을 때만 작동합니다. 비어 있으면 require_admin 은 검사 없이 통과시킵니다. 아래 시나리오를 따라가 보세요.

확인 결과

확인 완료(2026-09-12): 배포 환경에 ADMIN_PASSWORD 와 ADMIN_SECRET 이 모두 설정돼 있어 지금은 열려 있지 않습니다. 그래도 이 장을 남긴 이유는, 지금 안전한 근거가 코드가 아니라 설정 하나이기 때문입니다. 새 환경을 만들 때마다 같은 확인이 필요합니다. 자세한 내용은 {{sFIND}}장 F-01.
