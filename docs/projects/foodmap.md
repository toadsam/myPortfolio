# Ajou Campus Foodmap

> **증명하는 것**: JWT가 아닌 **세션 기반 인증**을 제대로 다뤄봤다는 것.
> 득근득근이 JWT라면 이건 세션 — **인증 방식 두 가지를 다 안다**는 게 이 프로젝트의
> 존재 이유다.

- 저장소 `toadsam/pwd-week6-client` · `toadsam/pwd-week6-server`
- 기간 2024.10 ~ 2024.12 · 개인 풀스택
- **현재 상세 페이지 없음** (카드만 있고 클릭해도 안 열림)

이 파일로 확인된다.

### PDF에 내용이 아주 잘 정리돼 있다 (35~42쪽, 8쪽 분량)

- **세션 + MongoStore** — 서버 재시작·재배포에도 로그인 유지
- **교차 도메인 세션** — `withCredentials` + CORS allowlist + credentials
- **Passport Local + bcrypt** — `UserSchema.pre('save')` 훅, saltRounds 12
- **OAuth 통합** — Google/Naver Strategy 분리 + `req.login()` 으로 세션 확정
- **스키마 검증** — `required` · `unique` · `index` + 상태 enum
  (`pending`/`approved`/`rejected`) 로 승인 워크플로우 고정
- **서버 중심 권한 검증** — 미들웨어로 프론트 우회 차단
- **환경 분기** — 환경변수로 API URL·DB 설정 분리

**이 정도 내용이 있는데 상세 페이지가 없다.** 지금은 카드 한 장에 링크 2개뿐이다.

## 🤖 코드로 만들 것

**상세 페이지를 만들기로 하면** 아래를 그린다. PDF 8쪽 분량이 있어서 재료는 충분하다.

1. **세션 인증 흐름 시퀀스** ⭐⭐⭐ — 이 프로젝트의 핵심.
   `로그인 → Passport Local → serialize → MongoStore 저장 → 쿠키 →
재요청 시 deserialize → 사용자 복원`
   **득근득근의 JWT 시퀀스와 나란히 두면 "두 방식을 비교할 줄 안다"가 된다.**
2. **교차 도메인 쿠키 도식** ⭐⭐ — `Vercel(프론트) ↔ Render(백엔드)` 가 도메인이
   다른데 쿠키가 오가야 한다. `withCredentials` + CORS allowlist + `SameSite`.
   신입이 잘 못 푸는 문제라 그림이 있으면 눈에 띈다.
3. **시스템 구성도** — `Vercel + Render + MongoDB Atlas` 3사 구성.
4. **승인 워크플로우 상태도** — `pending → approved / rejected` enum.

## ✋ 직접 만들 것

### 1. 상세 페이지를 만들지 결정 ⭐⭐⭐

지금은 **눌러도 아무 일이 없는 카드 3개 중 하나**다. 두 선택지가 있다.

- **만든다** — PDF 8쪽이 있어서 내용은 충분하다. 인증 방식 두 가지를 아는
  증거로 값어치가 있다.
- **안 만든다** — 카드에서 빼거나, 사이드 프로젝트로 내린다.

**만드는 쪽을 권한다.** 세션 인증은 JWT만 아는 지원자와 갈리는 지점이다.

### 2. 앱 실행 화면 ⭐⭐

Vercel + Render 배포였으니 아직 살아 있을 수도 있다. 죽었으면 로컬 실행.

- 맛집 목록 · 지도
- 맛집 등록 폼 (승인 워크플로우)
- 관리자 승인 화면 ← `pending/approved/rejected` 의 실체
- 로그인 (Local + Google/Naver)

### 3. 배포 주소 확인 ⭐⭐

Vercel/Render 무료 플랜은 방치하면 잠들거나 삭제된다. **살아 있으면 링크를 걸 것.**

| 질문                                    | 답할 재료                                                                                                    |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| JWT랑 세션 중 뭘 쓰나요?                | **둘 다 해봤다.** 득근득근은 JWT(무상태·확장), 이건 세션(서버 제어·즉시 무효화). 트레이드오프를 말할 수 있다 |
| 서버 재시작하면 로그인이 풀리지 않나요? | 그래서 MongoStore로 세션을 DB에 옮겼다. 재배포에도 유지된다                                                  |

| 비밀번호는 어떻게 저장했나요?           | `UserSchema.pre('save')` 훅에서 bcrypt 해싱(saltRounds 12). 원문 미저장                                      |
| 프론트에서 관리자 화면을 우회하면?      | 서버 미들웨어에서 인증·권한을 최종 검증한다. 프론트는 표시만 담당                                            |
| 왜 상세 페이지가 없나요?                | ← **지금 이 상태가 문제다.** 만들거나 카드에서 빼거나                                                        |
