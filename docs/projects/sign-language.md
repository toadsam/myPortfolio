2. **입력 데이터 처리 흐름** ⭐⭐ — 역할 설명에 "입력 데이터 처리"가 있다.

3. **API 목록** — Controller 6개는 적지만 역할이 뚜렷하다.

## ✋ 직접 만들 것

### 1. 앱 실행 화면 ⭐⭐⭐ — 3장

| 슬롯        | 필요한 화면                     |
| ----------- | ------------------------------- |
| 대표 (16:9) | 학습 메인 화면                  |
| 갤러리 ①    | 단어 학습 · 퀴즈                |
| 갤러리 ②    | 수어 동작 영상 재생 (3D 아바타) |
| 갤러리 ③    | 정답 피드백 · 반복 학습         |

팀 프로젝트라 실행 환경을 맞추는 데 시간이 걸릴 수 있다. **프론트만 띄워도**
화면은 나온다. 팀원에게 캡처를 부탁하는 것도 방법이다.

### 2. 라이브 데모의 "교체 예정" 문구 정리 ⭐⭐

지금 데모 하단에 **"(실제 모션 데이터로 교체 예정)"** 이라고 적혀 있다.
정직한 표기지만 **제출본에서 "예정"은 미완성으로 읽힌다.**
→ "동작 구조 시연" 정도로 바꾸거나 문구를 뺄 것.

### 3. 파란학기제 산출물 ⭐⭐

학기제 프로젝트라 **중간·최종 발표 자료, 보고서**가 반드시 있다.
거기에 문제 정의·시장 조사·화면 설계가 정리돼 있을 가능성이 높다.
표지·핵심 슬라이드 1~2장이면 "학교 정규 과정으로 수행했다"가 증명된다.

### 4. 팀 협업 흔적 ⭐⭐

4인 팀(FE 1 · BE 2 · 3D 1)인데 증거가 없다. **BE가 2명이면 역할을 어떻게
나눴는지**가 특히 궁금해진다 — API 분담표, PR 리뷰, 회의록.

### 5. 접근성 관점 자료 ⭐⭐

**이 프로젝트의 진짜 차별점은 기술이 아니라 문제 의식이다.**

- 농인 사용자 인터뷰·자문 기록
- 기존 서비스의 한계를 조사한 자료 (PDF에 _"기존 수어 플랫폼은 대부분 '문장을
  넣으면 아바타가 수어로 보여주는' 구조라, 이미 수어를 아는 사람을 전제한다"_
  라는 좋은 문제 정의가 있다)
- 실제 사용자 테스트

### 6. 수어 영상 제작 과정 ⭐

40개 영상을 어떻게 만들었는지 — 촬영? 모션 캡처? 자문? 그 과정 자체가 이야기다.
