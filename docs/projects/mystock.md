## 🤖 코드로 만들 것

1. **시스템 구성도** ⭐⭐⭐ — 이 프로젝트의 요점은 **외부 시세 연동의 폴백**이다.
   사이트에 이미 `MarketDataProvider: Yahoo Finance ↔ Demo(seed) 폴백 인터페이스`
   라고 적혀 있다. 그림으로 그리면 "외부 API가 죽어도 서비스가 산다"가 보인다.
   `docker-compose.yml` 이 있으니 컨테이너 경계도 같이 그린다.
2. **API 도메인 지도** ⭐⭐⭐ — Controller 25개를 기능 그룹으로.
   **"13"이라고 낮춰 적은 걸 바로잡는 가장 좋은 방법이다.**
3. **데이터 모델** — 금융 도메인(자산·거래·목표·지출·공시)은 모델링이 까다로워서
   ERD가 있으면 설득력이 크다.

## ✋ 직접 만들 것

### 1. 앱 실행 화면 ⭐⭐⭐ — 4장 필요

| 슬롯        | 필요한 화면                                    |
| ----------- | ---------------------------------------------- |
| 대표 (16:9) | 메인 대시보드                                  |
| 갤러리 ①    | 보유 종목 · 수익률                             |
| 갤러리 ②    | 자산 비중 차트                                 |
| 갤러리 ③    | AI 리서치 리포트 (`CompanyAnalysisController`) |
| 갤러리 ④    | MyWave 자산 흐름 대시보드                      |

**추가로 넣을 가치가 있는 것**: 재무 코치(`FinancialCoachController`),
공시/실적 화면 — 사이트에 아예 없는 기능들이다.

`docker-compose up` 으로 띄우면 되니 실행 장벽은 낮은 편이다.

> ⚠️ **본인 실제 투자 내역이 화면에 있으면 가릴 것.** 종목·금액·계좌는 민감하다.
> 데모 시드 데이터로 채운 화면을 찍는 게 안전하다.

### 2. 데이터 흐름도 ⭐⭐

`외부 시세 API → 캐시 → 계산(수익률·비중) → 화면`.
**"Yahoo Finance가 죽으면 어떻게 되나요"** 는 반드시 나오는 질문이고,
폴백 구조를 그림으로 두면 그 답이 미리 있다.

### 3. MyStock vs MyWave 구분 ⭐⭐

지금 제목이 `MyStock-Desk / MyWave` 인데 **둘이 뭐가 다른지 설명이 없다.**
한 저장소에 두 제품이 있는 이유, 각각 무엇인지 한 문단.

### 4. 실사용 여부 ⭐⭐

본인이 실제로 쓰고 있는지, 얼마나 오래 썼는지. **개인 도구는 "내가 매일 쓴다"가
가장 강한 증거다.** 사용 기간·기록 건수 정도면 충분하다.
