## PDF에 이미 정리된 내용 (27~34쪽)

상세 페이지를 만들면 그대로 재료가 된다.

- **시점 전환 시스템** — 1인칭 ↔ 탑다운. 카메라·컨트롤러·물리 제약을 함께 전환.
  `enum` 기반 switch로 모드 추가가 쉽게. 코루틴 지연으로 전환 직후 흔들림 방지
- **랜덤 스킬 성장** — 레벨업 시 `Time.timeScale = 0` → 3개 중 선택 → 즉시 반영.
  UI(표시)와 스킬(효과)의 책임 분리
- **적 AI** — NavMesh 배회/추적/공격 상태 전환 + 보스 랜덤 패턴(공격 전 예고)
- **UI ↔ 게임 월드 연동** — 인벤토리·장착·캐릭터 선택이 실제 오브젝트 상태로 반영
- **이벤트 시스템** — 돌발 퀘스트 · 포탈 씬 전환 · 소환 스킬 쿨타임

## 🤖 코드로 만들 것

**상세 페이지를 만들기로 하면:**

1. **시스템 모듈 구성도** ⭐⭐⭐ — PDF 29쪽에 이미
   `Player ↔ Skill ↔ UI ↔ AI ↔ Event` 상호 연결이라고 적혀 있다.
   **"각 시스템 독립적 확장 가능하도록 설계"** 가 이 프로젝트의 논지고,
   그건 그림으로만 증명된다.
2. **게임 루프 흐름도** ⭐⭐ — `탐색 → 전투/웨이브 → 경험치 → 레벨업 → 스킬 선택
→ 성장 → 다음 웨이브(난이도 상승)`
3. **AI 상태 전이도** ⭐⭐ — `Patrol → Chase → Attack`, `detectRange`/`attackRange`
   기반 분기 + 보스 랜덤 패턴
4. **시점 전환 상태도** — 1인칭 ↔ 탑다운, 전환 시 함께 바뀌는 것들

## ✋ 직접 만들 것

### 1. 상세 페이지를 만들지 결정 ⭐⭐⭐

PDF 8쪽이 있고 **1인으로 만든 3D 게임**이라 값어치가 있다. 만드는 걸 권한다.
다만 게임 프로젝트가 이미 4개(TSEROF·아주분투·DarkLab·이것)라 **웹 지원 이력서에서

→ **절충안**: 상세 페이지는 만들되, 카드 순서에서 웹 프로젝트 뒤로 둔다.

### 2. 인게임 화면 ⭐⭐⭐

플레이 영상(`mtIiIWmrSdg`)에서 뽑으면 5분이다.

- **1인칭 뷰 / 탑다운 뷰 비교** ← 시점 전환이 핵심 기능이라 이게 제일 중요하다
- 레벨업 스킬 선택 화면 (3개 중 선택)
- 보스 등장
- 인벤토리 · 캐릭터 선택
- 건물별 스테이지

PDF 30쪽에 "1인칭 화면과 탑다운 화면 비교" 이미지가 이미 있다.

### 3. 저장소 스크립트 확인 ⭐⭐⭐

위 ⚠️ 참고. **본인 코드가 올라가 있는지 확인**하고, 없으면 올릴 것.
"1인 개발"이라고 쓰는데 코드가 없으면 증명이 안 된다.

### 4. 아주대 마스코트 사용 확인 ⭐
