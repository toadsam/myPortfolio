# 아주분투

> **증명하는 것**: 게임을 만들면서 **자동 플레이테스트 하네스를 짰다**는 것.
> 이력서 13개 중 유일하게 "테스트를 자동화했다"를 말할 수 있는 프로젝트다.
>
> ⚠️ **「아주대탐험」과 다른 게임이다.** 그쪽은 Unity 3D, 이건 Phaser 2D.
> 저장소도 `Ajou_Mini_Game` / `Ajou_IndiGame` 으로 따로다. 이름이 비슷해 한 번
> 섞을 뻔했다.

- 저장소 `toadsam/Ajou_Mini_Game` · 개인 개발 (전담)
- 스택 TypeScript · Phaser 3 · Vite

### 자동 플레이테스트 하네스가 실물로 있다

`playtest-output` 계열 폴더가 **6개**다:

```
playtest-output/                    01-menu.png  02-started.png  …  playtest-log.json
playtest-output-pop-arc/            01-menu.png  02-started.png  08-final.png  09-game-over.png
playtest-output-pop-arc-2/
playtest-output-success-check/
playtest-output-verified/
playtest-output-overlap-high/
```

각 폴더에 **단계별 스크린샷 + `playtest-log.json` + `wire-debug.json`** 이 있다.
폴더 이름(`overlap-high`, `success-check`, `verified`)을 보면 **조건을 바꿔가며
반복 실행**한 흔적이다.

**이건 게임 프로젝트에서 아주 드문 자료다.** "자동 플레이테스트 하네스"라고
사이트에 한 줄 적혀 있는데, 실물 증거가 129개 파일로 저장소에 있다.

## 🤖 코드로 만들 것

1. **플레이테스트 하네스 흐름도** ⭐⭐⭐ — **이 프로젝트에서 가장 차별화되는 그림.**
   `시나리오 정의 → 자동 실행 → 단계별 캡처 → playtest-log.json → 판정`
   `playtest-output-*` 6개 폴더 이름이 곧 시나리오 목록이다.
2. **모듈 구조도** ⭐⭐ — 사이트에 이미 `Scene / Object / System 4·4·4` 라고
   적혀 있다. 그 모듈 분리를 그림으로.
3. **게임 루프 흐름도** — 발판 6종 · 낮/밤 전환.

## ✋ 직접 만들 것

### 1. 플레이테스트 산출물을 그대로 쓰기 ⭐⭐⭐ — 지금 당장 할 수 있다

**저장소에 이미 있다.** 새로 만들 필요가 없다.

- `playtest-output-*/01-menu.png` ~ `09-game-over.png` — **단계별 자동 캡처 연속샷**
- `playtest-log.json` — 실행 로그 (일부를 코드 창으로 보여줘도 좋다)

**연속샷 3~4장을 나란히 붙이면** "자동으로 게임을 돌려 검증했다"가 한눈에 보인다.
「개선 결과 화면」 21:9 슬롯에 딱 맞는다.

### 2. 프로토타입 → 최종 비교 ⭐⭐

문제 상황 슬롯 라벨이 **"도형 기반 초기 프로토타입"** 이다.
Phaser 초기 버전(도형만 있는 화면)이 커밋 히스토리에 남아 있을 가능성이 높다.
**있으면 Before/After가 완성된다** — 이 슬롯은 유일하게 채울 수 있는 4:3이다.

### 3. 실제 플레이 화면 ⭐⭐

웹 게임이라 배포가 쉽다. **GitHub Pages나 Vercel에 올리면 "직접 해보세요" 링크가
생긴다.** 사이트 메타에 `GitHub Pages / Vercel (정적)` 이라고 적혀 있는데
실제 주소가 없다 — 배포했다면 링크를 걸 것.

### 4. 발판 6종 · 낮밤 전환 자료 ⭐

부제에 있는 내용인데 보여주는 화면이 없다. 발판 종류별 캡처를 모아 한 장으로.
