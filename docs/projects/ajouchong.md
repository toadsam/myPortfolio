## 🤖 코드로 만들 것

1. **배포 파이프라인 도식** ⭐⭐ — `소스 → Docker 빌드 → Nginx 컨테이너 → 도메인`.
   저장소에 `Dockerfile` 2개 + `nginx.conf` 가 있으니 근거가 확실하다.
   **이 프로젝트에서 가장 차별화되는 그림이다.**
2. **SPA 라우팅 구조도** — `공지 → 상세 → 신청` 경로와 새로고침 404 대응
   (Nginx `try_files`). 지표에 "새로고침 404 = 0" 이라고 적어 뒀는데 그 근거가 여기다.

## ✋ 직접 만들 것

### 1. Before / After ⭐⭐⭐ — PDF에 이미 근거가 있다

PDF 18쪽:

> _"정보 유형(직책 / 국 / 담당 역할)을 명확히 구분하여 **카드형 구조로 재설계**"_ > _"기존 방식의 **가독성 문제를 개선**하기 위해 표(Table) 구조로 재구성"_ > _"제작 후 **실제 사용자 피드백을 반영**. 레이아웃·가독성·시각적 위계를 조정"_

**"개선했다"는 문장이 세 번 나오는데 개선 전 화면이 한 장도 없다.**

찾을 것:

- **조직도(국 소개)** 개편 전 화면
- **역대 총학생회** 표로 바꾸기 전 화면
- 피드백 반영 전/후

옛 커밋(`git log --diff-filter=D`), 발표 자료, 총학 내부 공유 문서에 있을 가능성.

### 2. 실제 서비스 화면 ⭐⭐

지금 2장뿐이다. 필요한 것:

- **조직도 페이지** (카드형 재설계의 결과물)
- **역대 총학생회 표**
- 행사·정책 목록
- 모바일 화면 (학생들은 폰으로 본다)

### 3. 운영 화면 ⭐⭐

"운영 중"이라는 주장의 근거. 공지 작성/관리 화면, 배포 로그, 서버 모니터링 등.
**단, 관리자 계정 정보·학생 개인정보는 반드시 가릴 것.**

### 4. 팀 협업 흔적 ⭐⭐

프론트 3인 팀인데 증거가 없다. 조직 저장소라 PR·이슈가 남아 있을 가능성이 높다.

### 5. Search Console 캡처 (선택) ⭐

출처를 라벨로 적어 뒀으니 필수는 아니다. 넣는다면 1장, 도메인만 보이게.
