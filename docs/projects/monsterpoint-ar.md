## PDF에 이미 정리된 내용 (49~55쪽)

- **Plane Detection → 전투 공간 고정** — 스캔 종료 시 탐지된 평면 boundary를
  **월드 좌표로 변환**해 바닥과 4방향 벽을 생성. 이후 전투는 그 영역 기준
- **boundary 기반 맵 생성** — boundary 점 수집 → min/max로 폭·길이 계산 →
  바닥 스케일링 + 벽 4개
- **스폰 포인트 자동 생성** — `floorCorners` 기반으로 스폰 위치를 만들고,
  게임 시작 후 스포너가 랜덤 이동 → **매 플레이마다 다른 전투 리듬**
- **웨이브 + 보스 트리거** — `spawnInterval` 스폰 루프, 처치 수(`counterBoss`)
  도달 시 보스 웨이브로 전환
- **무기 시스템** — 조이스틱 입력 방향이 있을 때만 발사, 무기별 `fireRate`,
  `nextFire` 쿨타임, `isUnlocked` 잠금. 무기 4종(화살·칼·마법·총)

**"현실 공간 크기에 따라 전투 경험이 달라진다"** 는 AR 게임의 본질을 건드린 설계다.

3. **무기 제어 흐름** ⭐ — 입력 방향 판정 → 잠금 확인 → 쿨타임 → 발사

## ✋ 직접 만들 것

### 1. Before / After 스캔 화면 ⭐⭐⭐ — PDF에 이미 있다

PDF 51쪽에 **"AR 스캔 전" / "전투 공간 고정 후"** 비교 이미지가 있다.
**AR 프로젝트에서 가장 설명력 있는 한 장**이다 — 평면 인식이 뭘 하는 건지
말로 설명할 필요가 없어진다.

### 2. 실제 플레이 사진 ⭐⭐⭐ — 화면 캡처보다 중요하다

**폰을 들고 현실 공간에서 플레이하는 사진.** AR은 화면만 보면 그냥 게임 같다.
현실 배경이 보여야 AR이라는 게 전달된다.

- 방/복도에 몬스터가 겹쳐 보이는 장면
- 플레이어가 움직이며 조준하는 모습
  > ⚠️ 사람 얼굴·집 내부 사생활이 나오면 가릴 것.

### 3. 공간 크기별 비교 ⭐⭐ — 이 프로젝트만의 자료

**같은 게임을 좁은 방과 넓은 공간에서 돌린 화면**을 나란히 두면,
"현실 공간이 난이도를 바꾼다"는 설계가 증명된다. 다른 어떤 프로젝트도 못 하는
종류의 증거다.

### 4. 무기 4종 화면 ⭐

화살·칼·마법·총. PDF 55쪽에 이미지가 있다.

### 5. 상세 페이지를 만들지 결정 ⭐⭐

VR과 묶어 **"XR 경험"** 한 덩이로 다루는 것도 방법이다. 웹 지원 이력서에서
게임/XR이 6개가 되는 건 부담이다.

| ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| AR에서 제일 어려웠던 건?     | 인식한 평면을 **게임 공간으로 고정**하는 것. boundary 점을 월드 좌표로 바꿔 바닥·벽을 만들어야 전투가 성립한다 |
