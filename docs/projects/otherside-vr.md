## PDF에 이미 정리된 내용 (43~48쪽)

- **MonsterAI** — 거리 기반 `Patrol → Chase → Attack` 상태 전환 +
  Enable 토글로 퍼즐과 연동해 **긴장감을 제어**
- **중앙 제어 구조(GameManager)** — Detector는 감지만, GameManager가 AI를 토글.
  결합도를 낮춰 트리거·퍼즐 조건을 추가하기 쉽게
- **VR 입력 → 특수 카메라 토글** — InputAction 기반 + **배터리(활성 시간) 제한**
- **렌더링 레이어 제어** — 카메라 모드 진입 시 PostFX ON + Hidden Objects 활성화.
  **"보이는 것"을 렌더링 레벨에서 규칙화**
- **리스크 관리 플레이** — 손전등을 켜면 적 감지 범위가 늘어난다

**"손전등을 켜면 잘 보이지만 들킬 확률이 올라간다"** 는 좋은 게임 디자인이고,
**"특수 카메라로만 보이는 단서"** 는 렌더링을 게임 규칙으로 쓴 사례다.

## 🤖 코드로 만들 것

**상세 페이지를 만들기로 하면:**

1. **AI 상태 전이도** ⭐⭐ — `Patrol → Chase → Attack` + 퍼즐 연동 토글.
   본인 담당 영역이라 이게 1순위다.
2. **중앙 제어 구조도** ⭐⭐ — `Detector(감지만) → GameManager(판단·토글) → AI(행동)`.
   **결합도를 낮춘 설계**가 이 프로젝트의 기술적 논지고, 그건 그림으로만 보인다.
3. **카메라 모드 상태도** — 일반 시야 ↔ 특수 카메라, 배터리 소모, PostFX·Hidden
   Object 토글

## ✋ 직접 만들 것

### 1. 상세 페이지를 만들지 결정 ⭐⭐

PDF 6쪽이 있다. 다만 **게임 프로젝트가 이미 4개**라 웹 지원 이력서에서 비중이
커진다. 만든다면 **AR과 묶어 "XR 경험" 한 덩이로** 다루는 것도 방법이다.

### 2. Before / After 화면 ⭐⭐⭐ — PDF에 이미 있다

PDF 47쪽에 **"BEFORE (카메라 OFF)" / "AFTER (카메라 ON)"** 비교 이미지가 있다.
**이 프로젝트에서 가장 강력한 한 장**이다 — 같은 공간인데 보이는 게 달라진다는 걸
한눈에 보여준다. PDF에서 뽑거나 영상에서 재캡처.

### 3. 인게임 화면 ⭐⭐

영상(`sK9OoBNCVvc`)에서 뽑으면 된다.

- 특수 카메라 착용 전/후
- 몬스터 추격 장면
- 어두운 저택 탐색

### 4. VR 플레이 사진 ⭐⭐ — 다른 프로젝트엔 없는 자료

**헤드셋을 쓰고 실제로 플레이하는 사진**이 있으면 "VR을 진짜 만들었다"가 즉시
전달된다. 화면 캡처만으로는 VR인지 알기 어렵다.

> ⚠️ 얼굴이 나오면 본인만, 팀원은 동의를 받거나 가릴 것.

### 5. 역할 정리 ⭐⭐

사이트 역할을 PDF 기준(**AI 몬스터 시스템 · 감지 로직 · 중앙 제어 구조**)으로
이미 고쳤다. 다만 PDF 5쪽 표에는 **"몬스터 개발 · 메인 기획"** 으로 되어 있어
PDF 안에서도 두 표기가 다르다. **어느 쪽이 맞는지 통일 필요.**

### 6. 팀 협업 흔적 ⭐⭐

팀장 저장소(`kbwon/IMP_VR`)에 협업한 프로젝트다. **PR·이슈가 남아 있으면
"남의 저장소에 기여했다"는 증거**가 되고, 이건 실무와 가장 비슷한 경험이다.
