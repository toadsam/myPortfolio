# 00. 메인 포트폴리오 전면 재설계 — 전체 개요

> **대상**: 마을에서 건물에 들어갔을 때 보이는 프로젝트 상세 화면
> (`viewMode === "project-interior"` → `ProjectInterior` → `ProjectViewer`)
> **비대상**: 이력서 모드(`ResumeMode` / `ProjectOnePager`) — 그건 정보 전달용이라 지금 구조 유지

---

## 1. 왜 갈아엎는가

### 지금 구조의 문제

```
ProjectViewer
  └ category(dashboard/realtime/platform/game) 로 4개 뷰어 중 하나 선택   ← 템플릿이 주인공
      └ RICH_RENDERERS → RichSection(step 0~4)                        ← 10개 프로젝트가 같은 5단계
          └ SIGNATURE[id] 데모를 step 0 맨 위에 얹기만 함              ← 개성은 곁다리
```

`shared.tsx`의 `RichProject` 인터페이스 하나에 10개 프로젝트가 전부 끼워 맞춰져 있다.
tldr → demo → meta → heroScreen → impact → features → problem → research → ... 순서가 **모든 프로젝트에서 동일**하다.
그래서 지금은 색깔(`projectThemes`)만 다르고, **화면 구조와 리듬은 10개가 전부 같다.**

### 바뀌는 원칙

| | Before | After |
|---|---|---|
| 주인공 | 카테고리 템플릿 | **프로젝트별 전용 화면** |
| 섹션 순서 | 개요→문제→접근→기여→결과 고정 | 프로젝트마다 다름 (스테이지형/타임라인형/관제형…) |
| 스크롤 축 | 전부 세로 | 세로 / 가로 / 스텝 점프 혼재 |
| 진입 | 공통 `ProjectIntro` (게임만 예외) | **10개 전부 다른 진입 연출** |
| 데모 | step 0 상단 부속품 | 화면의 중심, 또는 배경 그 자체 |
| 목적 | 정보 전달 | **체류 · 감탄 · 기억** |

### 지켜야 할 선

- 관람용이라고 **읽기를 포기하진 않는다**. 연출이 텍스트를 가리면 실패다.
- 모든 프로젝트에 **"연출 끄기 / 읽기 모드" 탈출구**를 둔다 (특히 darklab, ajou-adventure).
- 모바일에서 깨지면 안 된다. 각 문서의 `모바일 대응` 항목을 반드시 지킨다.
- 첫 화면 로드 3초 안에 "무슨 프로젝트인지"는 무조건 읽혀야 한다.

## 3. 문서 공통 표기 규칙

각 프로젝트 문서에서 아래 태그를 씁니다. **구현할 때 이 태그를 그대로 검색하면 할 일 목록이 됩니다.**

| 태그 | 뜻 | 예시 |
|---|---|---|
| `[IMG-nn]` | 이미지 슬롯. 없으면 대체 연출로 대신함 | `[IMG-03] 부스 지도 전체 화면 · 16:9 · 없으면 Leaflet 목업` |
| `[CODE-nn]` | 코드 스니펫 슬롯. 실제 저장소에서 가져올 것 | `[CODE-02] SSE 구독 훅 · 12줄 · 재연결 로직이 포인트` |
| `[NUM-nn]` | **실측 수치 필요.** 지어내지 말 것 | `[NUM-01] 부스 상태 반영 지연 (목표: ○ms)` |
| `[COPY]` | 화면에 그대로 들어갈 확정 문구 | |
| `[NEW]` | 새로 만들 컴포넌트 | |
| `[KILL]` | 삭제/미사용 처리할 기존 코드 | |

### `[NUM]` 처리 원칙

`projects.ts`에는 측정된 숫자가 없다. 없는 숫자를 만들어 넣으면 면접에서 바로 무너진다.
따라서 각 문서의 수치 자리는 세 등급으로 표시한다.

1. **확정** — 코드/저장소에서 셀 수 있는 것 (화면 수, API 수, 기술 스택 수, 커밋 수, 개발 기간)
2. `[NUM]` — 측정하면 나오는 것 (번들 크기, 렌더 시간, Lighthouse 점수) → **측정하고 채울 것**
3. **삭제** — 측정 불가능한 것 (사용자 수, 만족도) → 숫자 대신 정성 문장으로 대체

## 4. 공통 구현 규약

### 4-1. 구조 전환

```
[KILL] DashboardProjectViewer / RealtimeProjectViewer / PlatformProjectViewer / GameProjectViewer
       → 4개 카테고리 뷰어는 폴백 1개로 축소 (FallbackProjectViewer)

[KILL] shared.tsx 의 RichSection (5단계 고정 렌더러)
       → 프레젠테이션 컴포넌트(CodeBlock, ImageSlot, CountUp, DecodeText, RevealText,
          Magnetic, MockScreen, DemoFrame)는 전부 살려서 공용 킷으로 유지
       → 순서를 강제하던 RichSection 본체만 제거

[NEW] src/components/ui/project-viewers/stages/<projectId>/index.tsx
       → 프로젝트 1개 = 폴더 1개. 그 안에서 자기 섹션 순서를 직접 결정한다.

[NEW] ProjectStage 인터페이스
       { id, enter, sections, exit, chrome }  ← 프로젝트별로 자유 구현
```

### 4-2. 살려서 재사용할 공용 킷 (`shared.tsx`)

전부 이미 있고 품질도 좋다. **다시 만들지 말 것.**

| 컴포넌트 | 용도 |
|---|---|
| `CodeBlock` / `CodeLine` | 파일명 헤더 + 라인번호 + 하이라이트 코드 |
| `ImageSlot` | src 없으면 플레이스홀더, 클릭 시 라이트박스 |
| `MockScreen` | dashboard/bars/cards/feed/stats/title 목업 |
| `CountUp` | 뷰포트 진입 시 숫자 롤업 |
| `DecodeText` | 글자 스크램블 → 확정 |
| `RevealText` | 단어 단위 페이드업 + 기술 키워드 하이라이트 |
| `Magnetic` | 커서 끌림 |
| `DemoFrame` | 라이브 데모 패널 틀 |

### 4-3. 성능 가드

- 무거운 연출(캔버스, 파티클, WebGL)은 **뷰포트 밖이면 정지**. `IntersectionObserver` 필수.
- `prefers-reduced-motion: reduce` 존중 — 모션 대신 즉시 최종 상태.
- 진입 연출은 **최대 2.5초**. 그 이상은 관람이 아니라 대기다. 항상 스킵 가능.
- 프로젝트 폴더는 `dynamic(() => import(...), {ssr:false})` 로 개별 코드 스플릿.

### 4-4. 공통으로 남는 것

- `SoundToggle` — 모든 프로젝트에 유지. 단, **기본값은 프로젝트마다 다름** (수어지구는 OFF 고정)
- `atmosphere.ts` / `AmbientBackground` — 유지하되, 프로젝트 전용 배경이 있으면 그쪽이 우선
- `sound.ts` WebAudio 신스 — 프로젝트별 사운드 성격을 각 문서의 `아트 디렉션`에 명시

## 5. 작업 순서 제안

한 번에 10개를 다 갈아엎지 말고, **가장 임팩트 큰 순서**로.

1. **DarkLab** — 연출 차이가 가장 극적. "이 포트폴리오 뭔가 다르다"를 만드는 첫 카드
2. **FestFlow** — 기술적 깊이(SSE) 어필이 가장 좋음. 대표 프로젝트
3. **아주대모험** — 실제 플레이 가능 = 체류시간 압도적
4. **득근득근** — 게임화 컨셉이 화면과 딱 맞아떨어짐
5. **MyStock-Desk** → **MyWave** → **TSEROF** → **ACLUB** → **수어지구** → **아주총학**

각 프로젝트 1개당 예상: 전용 화면 1~2일 + 시그니처 인터랙션 0.5~1일.
