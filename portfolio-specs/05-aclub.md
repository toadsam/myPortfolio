# 05. ACLUB — 「동아리 박람회 포스터 월」

> 동아리 탐색·모집 캠퍼스 플랫폼 프론트엔드 · React / TypeScript / Vite / Tailwind
> 테마: `primary #c084fc` / `secondary #a855f7` / `bg #0d0816` / `accent #d8b4fe`

---

## 0. 한 줄 컨셉

**"신입생 환영회 주간, 학생회관 복도의 포스터 벽 앞에 선다."**

벽면 가득 동아리 포스터가 붙어 있다. 색도 크기도 제각각이다.
상단에서 태그를 고르면 **포스터들이 실제로 자리를 옮기며 재배치된다.**

이 프로젝트는 백엔드가 없다. 순수 프론트엔드다. 그러니까 **"화면을 어떻게 만들었는가"로만 승부해야 한다.**
그렇다면 이 페이지 자체가 그 증거가 되어야 한다 — 필터가 진짜로 동작하고, 재배치가 부드럽고, 상태 관리가 깔끔한 화면.

## 1. 아트 디렉션

| 항목 | 값 |
|---|---|
| 배경 | `#0d0816` + 벽 질감 (아주 옅은 노이즈 + 상단 스포트라이트 `radial-gradient(#c084fc10, transparent 55%)`) |
| 주색 | `#c084fc` 퍼플 |
| 포스터 색 | **포스터마다 다른 색.** 퍼플 계열 3 + 청록 2 + 앰버 2 + 로즈 2 — 벽이 알록달록해야 박람회다 |
| 타이포 | 헤딩 = `font-black` / 포스터 제목 = 큼직하게 / 본문 = 산세리프 `leading-8` |
| 모서리 | `rounded-lg` + 포스터에 **아주 살짝 회전** (`rotate: -1.5deg ~ 1.5deg` 랜덤) — 손으로 붙인 느낌 |
| 그림자 | 포스터에 `0 8px 24px rgba(0,0,0,0.4)` — 벽에서 살짝 떠 있게 |
| 모션 톤 | **FLIP 재배치가 주인공.** `layout` 애니메이션 `type: spring, stiffness 260, damping 26` |
| 사운드 | variant `calm`. 필터 클릭 = 종이 넘기는 소리 톤(짧은 노이즈 버스트). 조용한 편 |

### 이 프로젝트만의 장치
- **포스터에 압정/마스킹테이프**: 각 카드 상단에 작은 원(압정) 또는 반투명 테이프 조각 하나. CSS만으로.
- 이거 하나로 "카드 UI"가 "벽에 붙은 포스터"가 된다. **비용 대비 효과가 제일 큰 디테일.**

## 2. 진입 연출 (0 → 2.2초)

**포스터가 벽에 붙는다.**

```
0.0s  빈 벽. 스포트라이트만 위에서 내려옴
0.3s  포스터 9장이 화면 밖(위쪽)에서 하나씩 떨어져 벽에 붙음
      - 0.07s 간격, 각자 다른 최종 회전각으로 착지
      - 착지할 때 살짝 오버슈트 (스프링)
      - 종이 소리 9회
1.2s  상단에 필터 칩 바가 슬라이드 인
1.5s  타이틀 오버레이
        ACLUB
        동아리 정보는 늘 흩어져 있었다
2.0s  오버레이 페이드아웃 — 포스터 벽만 남음
2.2s  스크롤 활성화
```

- **스킵**: 클릭/키/스크롤 → 2.0s 상태로
- `reduced-motion` → 포스터 전부 즉시 배치, 회전 없이 정렬

## 3. 섹션 구성

**레이아웃 대원칙**: 세로 스크롤. **포스터 벽(그리드)이 히어로이자 시그니처**로 맨 위에 크게 오고,
그 아래로 문제/설계/기여/결과가 이어진다.
FestFlow처럼 sticky를 쓰지 않는다 — **이 프로젝트는 "한 번 크게 보여주고 설명으로 넘어가는" 구조.**

```

├───────────────────────────────────────────────────────────────┤

│                                                               │
│   ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐                      │
│   │ 📌   │  │ 📌   │  │ 📌   │  │ 📌   │                       │
│   │ 포스터│  │ 포스터│  │ 포스터│  │ 포스터│   ← 이게 시그니처   │
│   └──────┘  └──────┘  └──────┘  └──────┘                      │
│   ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐                      │
│   │      │  │      │  │      │  │      │                      │
│   └──────┘  └──────┘  └──────┘  └──────┘                      │
│                                                               │
│  ─────────────────────────────────────────────────────────    │
│                                                               │
```

### S2. 탐색 → 상세 → 지원, 하나의 흐름 — 설계

이 프로젝트의 핵심은 **긴 사용자 흐름을 화면으로 쪼갠 것**이다. 그래서 플로우 다이어그램이 주인공.

```
 [ 목록 ]──▶[ 필터 ]──▶[ 상세 ]──▶[ 모집 공고 ]──▶[ 지원 ]
    │                      │                        │
    └──────────────────────┴────────────────────────┘
                    ↓ 마이페이지에서 확인
              [ 지원 현황 ]
```

**[NEW]** `UserFlowTrack` — 위 플로우를 **가로 트랙**으로 그리고, 노드를 클릭하면
그 화면의 스크린샷/목업이 아래에 교체되며 나타난다. (탭 + 미리보기 결합)

**[COPY-05]**
> 처음엔 목록 한 화면에 필터, 상세, 지원을 다 넣으려고 했다.
> 만들고 보니 화면 하나가 상태를 여섯 개 들고 있었다.
> **화면을 쪼개는 건 UI 문제가 아니라 상태 관리 문제였다.**

**기술 의사결정** (`DecisionTable` 재사용):

| 영역 | 선택 | 이유 | 대안 |
|---|---|---|---|
| 라우팅 | 화면 단위 분리 | 화면 하나 = 상태 하나. 뒤로가기가 자연스러움 | 단일 페이지 모달 — 상태 폭발 |
| 상태 | 지역 상태 우선 | 전역이 필요한 건 인증뿐이었다 | 전역 스토어 — 이 규모엔 과함 |
| 빌드 | Vite | HMR 속도. 화면 6개를 계속 갈아엎어야 했음 | CRA — 느림 |
| 타입 | TypeScript 전면 | 동아리/공고/지원 3개 도메인이 서로 참조 | JS — 필드 오타로 이미 한 번 데임 |

- **[CODE-01]** 필터 로직 (다중 조건 조합) · **12~18줄** · `useClubFilter.ts`
  포인트: 필터가 **누적 조건**으로 합성되는 부분. `reduce` 또는 조건 배열 하이라이트
- **[CODE-02]** 라우팅 구조 + 보호 라우트 · **10~14줄**
  포인트: 관리자 화면 분리

### S3. 역할을 나누니 화면이 정리됐다

**[COPY-06]**
> 일반 사용자와 관리자를 같은 화면에서 권한으로 나누려다가 포기했다.
> **관리자에게 필요한 건 "동아리를 고르는 화면"이 아니라 "동아리를 관리하는 화면"이었다.**
> 목적이 다르면 화면도 달라야 한다.

```
┌────────────────────────┬────────────────────────┐
│  일반 사용자            │  관리자                 │
│  목적: 고른다           │  목적: 관리한다          │
│  ─────────────         │  ─────────────         │
│  탐색 · 필터            │  동아리 등록/수정        │
│  상세 조회              │  모집 공고 관리          │
│  지원                   │  지원자 조회             │
│  마이페이지             │                        │
└────────────────────────┴────────────────────────┘
```

## 4. 시그니처 인터랙션 — 「진짜 작동하는 필터 + FLIP 재배치」

**[NEW]** `PosterWall` (기존 `AClubDemo.tsx` 를 이 컨셉으로 재작성)

**핵심 주장**: "필터를 만들었습니다"라고 쓰는 대신, **여기서 직접 써보게 한다.**

```
[ 전체 12 ] [ 공연 4 ] [ 체육 3 ] [ 학술 3 ] [ 봉사 2 ] [ 모집중 ● 5 ]
                                                          ↑ 토글 (중복 선택 가능)
┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
│   📌   │ │   📌   │ │   📌   │ │   📌   │
│ 밴드부  │ │ 축구부  │ │ 알고리즘│ │ 사진부  │
│ 공연    │ │ 체육    │ │ 학술    │ │ 문화    │
│ 모집중 ●│ │ 마감    │ │ 모집중 ●│ │ 모집중 ●│
└────────┘ └────────┘ └────────┘ └────────┘
```

### 동작 명세
1. **12장의 포스터**를 데이터로 정의 (`clubs.ts`). 각각 이름/카테고리/모집상태/색상/회전각
2. 필터 칩 클릭 → 조건에 안 맞는 포스터는 `AnimatePresence` 로 **떨어지듯 사라지고** (y: 40, opacity 0, rotate 랜덤)
   남은 포스터들은 `layout` 으로 **자리를 옮긴다** (FLIP)
3. 이게 이 데모의 전부다. **부드러운 재배치 하나에 모든 걸 건다.** 어설프면 오히려 마이너스
4. 칩에 **결과 개수 실시간 표시** — `전체 12` → `공연 4`. 필터가 진짜 도는 증거
5. 결과 0건이면 빈 벽 + `조건에 맞는 동아리가 없습니다` (실제 서비스의 empty state를 그대로 재현)
6. 포스터 hover → 살짝 떠오르며 회전이 0도로 펴짐 + 그림자 강해짐
7. 포스터 클릭 → 상세 미리보기 패널이 아래로 펼쳐짐 (아코디언). 모집 마감일, 활동 요일, 인원

### 왜 이게 시그니처인가
백엔드 없는 프로젝트에서 **"프론트엔드를 잘한다"를 증명하는 가장 직접적인 방법**이 이거다.
말로 "필터링 구현" 열 줄 쓰는 것보다, 관람객이 칩 3번 눌러보는 게 훨씬 강하다.

### 성능
- 12장 정도면 `layout` 애니메이션 부담 없음. 단, `layoutId` 남발 금지
- 회전각은 **마운트 시 한 번만 계산**해서 고정 (매 렌더 랜덤이면 필터 때마다 각도가 바뀌어 어지럽다)

### 모바일
- 그리드 4열 → 2열
- 필터 칩 바는 가로 스크롤 (`overflow-x-auto`, 스크롤바 숨김)
- 포스터 회전각을 ±0.8deg로 줄임 (작은 화면에서 큰 회전은 지저분함)
