> ⭐ **대표 프로젝트.** 기술 깊이(SSE 실시간)와 서사(축제 현장)가 둘 다 있는 유일한 프로젝트다.

## 0. 한 줄 컨셉

**"축제 밤, 운영 본부 텐트 안에 앉는다."**

머리 위에 전구줄이 흔들리고, 눈앞엔 캠퍼스 지도가 펼쳐져 있다.
지도 위 부스 핀들이 **실시간으로 색을 바꾼다** — 운영중(초록) / 혼잡(앰버) / 마감(회색).
옆에는 이벤트 로그가 계속 쌓인다.

관람객은 이 화면을 보고 3초 안에 알아야 한다: **"아 이게 실시간이구나."**
그게 이 프로젝트가 증명해야 하는 단 하나다.

| 타이포 | 헤딩 = 굵은 산세리프 `font-black` / 로그·좌표 = `font-mono` / 본문 = 산세리프 `leading-8` |
| 모서리 | `rounded-xl` |

### 이 프로젝트만의 장치
- **전구줄(string lights)**: 화면 최상단을 가로지르는 전구 8~12개. 아주 느리게 흔들리고(±2°), 밝기가 미세하게 호흡한다. **모든 섹션에서 상시.**
- **LIVE 인디케이터**: 헤더에 맥동하는 점 + `LIVE` — `DemoFrame`의 기존 맥동 도트 스타일 재사용

## 2. 진입 연출 (0 → 2.5초)

**밤 → 축제 점등.**

```
0.0s  거의 검은 화면. 캠퍼스 지도 윤곽선만 아주 희미하게 (opacity 0.08)
0.4s  전구줄이 좌→우로 순차 점등 (0.06s 간격, 12개) + 딸깍 사운드
      점등될 때마다 지도가 조금씩 밝아짐
1.0s  지도가 완전히 드러남 + 축제 웅성거림 페이드인
1.2s  부스 핀 9개가 지도 위로 **팝**하며 등장 (0.05s 간격, 스프링, 위→아래 착지)
      각 핀은 등장하자마자 자기 상태 색을 가짐
1.9s  타이틀이 지도 위 오버레이로
        FestFlow
        축제 현장은 1분마다 바뀐다
2.3s  오버레이 페이드아웃, 지도는 그대로 남아 sticky 패널로 전환
2.5s  이벤트 로그가 하단에서 슬라이드 인 + 첫 이벤트 도착
```

- **스킵**: 클릭/키/스크롤 → 2.3s 상태로
- `reduced-motion` → 전구 즉시 전부 켜짐, 핀 즉시 배치, 흔들림 없음

## 3. 섹션 구성

**레이아웃 대원칙**: 지도가 **오른쪽에 sticky**로 계속 붙어 있고, 왼쪽 텍스트가 흐른다.
(MyWave와 좌우가 반대 — 나란히 놓고 봐도 안 헷갈리게)
그리고 결정적으로: **왼쪽 섹션이 바뀔 때마다 오른쪽 지도가 그 섹션에 맞게 반응한다.**

| 왼쪽 섹션 | 오른쪽 지도의 반응 |
|---|---|
| S0 히어로 | 전체 뷰, 핀 9개 정상 상태, 로그 흐름 |
| S1 문제 | 지도가 **회색으로 탈색** + 핀들이 전부 `?` 물음표로 (상태를 모르는 상황) |
| S2 SSE 설계 | 서버→클라 연결선이 지도 위에 그려짐. 이벤트가 선을 타고 날아와 핀에 꽂힘 |
| S3 권한 분리 | 지도에 3개 반경 오버레이 (관리자=전체 / 스태프=담당 구역 / 사용자=공개 정보만) |
| S4 PWA | 지도 우상단에 `오프라인` 뱃지 + 지도 타일이 캐시 버전으로 |
| S5 결과 | 전체 뷰 복귀, 핀 상태 정상, 로그 최고조 |

> **이게 이 문서에서 가장 중요한 표다.** sticky 지도가 스크롤에 반응하는 것 자체가 시그니처다.

```
┌───────────────────────────────────────────────────────────────┐
│  ✧  ✧  ✧  ✧  ✧  ✧  ✧  ✧  ✧  ✧  ✧  ✧   ← 전구줄 (상시)      │
├───────────────────────────────────────────────────────────────┤
│ ← 마을로   FestFlow          ● LIVE      🔊  [읽기 모드]      │
├────────────────────────────┬──────────────────────────────────┤
│                            │  ┌────────────────────────────┐  │
│   S0. FestFlow             │  │                            │  │
│   S1. 무전기로는 안 됐다    │  │      캠퍼스 지도            │  │
│   S2. SSE — 왜 소켓이       │  │   ● ● ●  ← 부스 핀          │  │
│       아니었나              │  │     ●  ●                   │  │
│   S3. 역할이 다르면          │  │   ●   ● ●                  │  │
│       화면도 달라야          │  │                            │  │
│   S4. 현장에 와이파이는      │  └────────────────────────────┘  │
│       없다 (PWA)            │  ┌────────────────────────────┐  │
│   S5. 결과                  │  │ ▸ LIVE FEED                │  │
│                            │  │ 20:14 푸드트럭 A 혼잡       │  │
│                            │  │ 20:13 공연장 입장 마감      │  │
│                            │  │ 20:11 부스 12 운영 시작     │  │
│                            │  └────────────────────────────┘  │
└────────────────────────────┴──────────────────────────────────┘
         52%                            48% (sticky)
```

### S2. SSE — 왜 WebSocket이 아니었나 ⭐

**이 섹션이 이 프로젝트의 기술적 심장이다. 가장 공들일 것.**

**[COPY-05]**
> 실시간이라고 하면 보통 WebSocket을 떠올린다. 나도 그랬다.
> 그런데 우리가 필요한 건 **서버가 일방적으로 밀어주는 것**뿐이었다.
> 부스 상태를 바꾸는 건 관리자의 REST 요청이고, 클라이언트는 받기만 하면 됐다.

```
┌─────────────────────────────────────────────────────────────┐
│  ▸ 양방향이 필요한가?                                        │
│                                                             │
│    WebSocket              SSE                               │
│    ──────────             ───                               │
│    ⇄ 양방향               → 서버 → 클라 단방향               │
│    별도 프로토콜           그냥 HTTP                          │
│    프록시/방화벽 이슈       프록시 그대로 통과                 │
│    재연결 직접 구현         브라우저가 자동 재연결             │
│    ─────────────────────────────────────────                │
│    필요 없는 것에           우리 요구에 정확히                │
│    비용을 냄               맞음  ✓                           │
└─────────────────────────────────────────────────────────────┘
```

**[COPY-06]** (결정 근거 — 이 문장이 면접 답변 그 자체가 되도록)
> 축제 현장은 학교 와이파이와 LTE가 섞인다. 프록시를 그대로 통과하고,
> 연결이 끊겨도 브라우저가 알아서 다시 붙는다는 점이 결정적이었다.
> 양방향이 필요 없는데 양방향 인프라를 유지하는 건 그냥 부채였다.

- **[CODE-01]** 서버 SSE 발행 · **14~20줄** · `BoothEventController.java` / `SseEmitter` 부분
  포인트: `SseEmitter` 등록·해제, 타임아웃, 브로드캐스트. **emitter 정리(remove) 부분 하이라이트** — 여기서 메모리 누수 얘기를 꺼낼 수 있다.
- **[CODE-02]** 클라이언트 구독 훅 · **12~18줄** · `useBoothStream.ts`
  포인트: `EventSource` 생성, `onmessage` 파싱, **cleanup에서 close** 하이라이트
- **[CODE-03]** 재연결 / 중복 이벤트 처리 · **8~14줄**
  포인트: 재연결 후 상태 재동기화. 이게 있으면 "실무 감각 있다"로 읽힌다.

**[NEW]** `SseFlowDiagram` — 지도 sticky 패널과 연동.
이 섹션에 스크롤이 닿으면 지도 위에 **서버 노드 → 각 핀으로 향하는 선**이 그려지고,

### S3. 역할이 다르면 화면도 달라야 한다 — 권한

**[COPY-07]**
> 같은 부스 데이터를 봐도 필요한 게 다르다.
> 관리자는 전체 현황과 매출, 스태프는 자기 구역의 할 일, 방문자는 어디가 한가한지.
> 처음엔 한 화면에 다 넣고 권한으로 숨겼는데, **숨긴 정보가 있는 화면은 항상 어수선했다.**
> 결국 화면 자체를 역할별로 분리했다.

```
┌──────────────┬──────────────┬──────────────┐
│  관리자       │  스태프       │  방문자       │
│  ──────      │  ──────      │  ──────      │
│ 전체 부스     │ 담당 구역만   │ 지도 + 혼잡도 │
│ 스태프 관리   │ 상태 변경     │              │
│ 통계 대시보드 │ 요청 접수     │              │
│              │              │              │
│ JWT: ADMIN   │ JWT: STAFF   │ 인증 없음     │
└──────────────┴──────────────┴──────────────┘
   ↑ 탭으로 전환 — 클릭하면 sticky 지도가 그 역할 시점으로 바뀜
```

**[NEW]** `RoleSwitcher` — 3개 탭. 클릭하면:
- 지도 오버레이가 해당 역할의 가시 범위로 변경 (관리자=전체 밝음 / 스태프=담당 구역 외 어둡게 / 방문자=핀은 보이되 상세 라벨 숨김)
- 좌측에 그 역할이 볼 수 있는 화면 목록이 교체
- **관람객이 직접 역할을 갈아타보는 경험** — 권한 설계를 말이 아니라 조작으로 이해시킴

### S4. 현장에 와이파이는 없다 — PWA

**[COPY-08]**
> 축제 부스는 대부분 야외다. 학교 와이파이는 사람이 몰리면 먼저 죽는다.
> 스태프가 상태를 바꾸려는 순간 네트워크가 끊기면, 그 앱은 현장에서 버려진다.

```
┌───────────────────────────────────────────────┐
│  ▸ OFFLINE MODE                    [ 끊기 ⚡ ] │
│                                               │
│   연결 상태   ● 온라인  →  ○ 오프라인          │
│                                               │
│   지도 타일     캐시에서 로드  ✓               │
│   부스 목록     마지막 상태 표시  ✓            │
│   상태 변경     큐에 저장 (2건 대기)  ⏳        │
│                                               │
│   → 재연결 시 자동 전송                        │
└───────────────────────────────────────────────┘
```

**[NEW]** `OfflineToggleDemo` — `[ 끊기 ⚡ ]` 버튼을 관람객이 직접 누른다.
누르면 sticky 지도에 `오프라인` 뱃지가 뜨고, LIVE 피드가 멈추고, 지도가 캐시 버전(약간 desaturate)으로 바뀐다.
다시 누르면 밀린 이벤트가 한꺼번에 로그에 쏟아진다. ← **이 "한꺼번에 쏟아짐"이 관람 포인트.**

- **[CODE-05]** Service Worker 캐시 전략 · **10~16줄** · `sw.js` / workbox 설정
  포인트: 지도 타일은 CacheFirst, API는 NetworkFirst — **전략을 나눴다는 것**이 보이게

## 4. 시그니처 인터랙션 — 「라이브 관제 지도」

**[NEW]** `FestControlMap` — 이 프로젝트 전체를 지배하는 sticky 컴포넌트.
(기존 `FestFlowLiveDemo.tsx` 를 이 규모로 확장 재작성)

### 구성
```
┌────────────────────────────────────┐
│  캠퍼스 지도 (SVG 또는 Leaflet)      │
│                                    │
│    ●운영중  ●혼잡  ○마감            │
│      ● 푸드트럭 A                   │
│         ● 공연장                    │
│    ● 부스 12    ● 플리마켓          │
│                                    │
│  [범례] 운영중 · 혼잡 · 마감 · 긴급  │
└────────────────────────────────────┘
┌────────────────────────────────────┐
│ ▸ LIVE FEED              ● LIVE    │
│ 20:14  푸드트럭 A  →  혼잡         │  ← 새 항목이 위에서 밀려 들어옴
│ 20:13  공연장     →  입장 마감      │
│ 20:11  부스 12    →  운영 시작      │
└────────────────────────────────────┘
```

### 동작 명세
1. **자동 이벤트 루프**: 2.5~4초 랜덤 간격으로 부스 하나의 상태가 바뀐다.
   - 핀이 `scale 1 → 1.35 → 1` 스프링 팝 + 새 색으로 전환
   - 핀에서 파문 링 1개가 퍼짐 (`scale 1→2.6, opacity 0.5→0`)
   - 로그 최상단에 한 줄 삽입 (기존 항목들은 아래로 밀림, `layout` 애니메이션)
   - 사운드 ON이면 짧은 `핑`
2. **핀 클릭**: 해당 부스 상세 툴팁 (이름 / 상태 / 마지막 변경 시각 / 대기 인원)
3. **관람객 개입**: 툴팁에 `[ 상태 바꾸기 ]` 버튼 → 직접 상태를 바꿀 수 있다.
   → 바꾸면 로그에 `👤 방문자가 변경` 으로 기록됨. **자기가 만든 이벤트가 로그에 남는 경험.**
4. **섹션 연동**: 위 §3의 표대로 좌측 스크롤 위치에 따라 지도 모드가 전환된다.
   `IntersectionObserver` 로 현재 활성 섹션 id를 추적 → 지도에 `mode` prop 전달
5. **일시정지**: 우상단 `⏸` — 로그를 읽고 싶은 사람을 위해. 뷰포트 이탈 시 자동 정지.

### 지도 구현
- **Leaflet 실제 사용 X** (번들 무겁고 타일 외부 요청). **인라인 SVG로 캠퍼스 약도**를 그린다.
  - 건물 블록 6~8개를 둥근 사각형으로, 길을 선으로. 실제 아주대 배치를 단순화
  - 이게 오히려 "축제 팸플릿 약도" 느낌이 나서 컨셉에 더 맞다
- **[IMG-08]** (선택) 실제 서비스의 Leaflet 지도 스크린샷 — S5 결과 섹션에 별도로 배치해서 "실제로는 Leaflet을 썼다"를 증명

### 성능
- 이벤트 루프는 `setTimeout` 체인. 언마운트/뷰포트 이탈 시 정리
- 로그는 **최대 12개 유지**, 넘으면 아래에서 제거 (`AnimatePresence` exit)
- 핀 파문은 동시에 최대 3개

### 모바일 (`< 1024px`)
- 좌우 분할 해제. 지도를 **화면 상단 sticky (높이 40vh)** 로, 텍스트가 그 아래로 흐름
- LIVE 피드는 지도 하단에 3줄만 (`overflow` 잘라냄)
- 역할 전환 탭은 가로 스크롤 칩으로
