# 06. 아주총학 — 「학생회관 공지 게시판」

> 아주대학교 총학생회 공식 웹사이트 프론트엔드 · React / React Router / JavaScript / **Docker / Nginx**
> 테마: `primary #fb7185` / `secondary #f43f5e` / `bg #160709` / `accent #fda4af`

## 0. 한 줄 컨셉

**"이 포트폴리오에서 유일하게, 실제 학생들이 쓴 서비스."**

10개 프로젝트 중 **실제 배포되어 운영된 건 이것뿐이다.** 그게 이 프로젝트의 전부이자 유일한 무기다.
다른 프로젝트가 "만들었습니다"라면 이건 "**돌아갔습니다**"다.

그래서 화면 컨셉도 둘로 나뉜다:
- **앞면**: 학생회관 복도 게시판 — 종이 공지가 붙어 있는 아날로그 질감
- **뒷면**: 그 게시판 뒤에서 돌아가는 배포 파이프라인 — 커밋 → 빌드 → 컨테이너 → 라이브

**앞면(학생이 본 것)과 뒷면(내가 만든 것)을 뒤집어 보여주는 것**이 이 프로젝트의 연출이다.

## 2. 진입 연출 (0 → 2.2초)

```
0.0s  어두운 코르크보드
0.4s  공지 종이 3장이 위에서 툭툭 붙음 (0.15s 간격, 아주 살짝 회전하며 착지)
      종이 소리 3회
1.0s  가장 큰 종이의 텍스트가 위에서부터 드러남 (clip-path 아래로 확장)
        아주대학교 총학생회
        공지사항 · Q&A · 복지
1.6s  화면 우하단에 작은 터미널 창이 슬라이드 인
        $ docker compose up -d
        ✓ nginx  running
1.9s  터미널 창 위에 뱃지  ● 실제 배포 · 운영됨
2.2s  스크롤 활성화
```

- 1.6s의 터미널 등장이 이 프로젝트의 킥이다. **"이건 실제로 돌아갔다"를 진입 3초 안에 박아넣는다.**
- **스킵**: 클릭/키/스크롤 → 1.9s 상태로
- `reduced-motion` → 종이 즉시 배치, 회전 없음

## 3. 섹션 구성

**레이아웃 대원칙**: 세로 스크롤 + **뒤집기(flip) 구조**.
S0~S2는 "게시판 앞면"(학생 시점), S3~S4는 "게시판 뒷면"(개발자 시점).
전환 지점에서 화면 전체가 **Y축으로 180° 뒤집히는 연출**이 들어간다. ← 이 프로젝트만의 구조

```
┌───────────────────────────────────────────────────────────────┐
│ ← 마을로   아주총학     ● 실제 배포됨      🔊  [읽기 모드]     │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│   ═══ 앞면 · 학생이 본 화면 ═══                                │
│                                                               │
│   ┌─────────────┐  ┌─────────────┐                            │
│   │  공지사항    │  │    Q&A      │   ← 아이보리 종이           │
│   │  ─────      │  │   ─────     │                            │
│   │  · 등록금... │  │  Q. 복지... │                            │
│   │  · 학사일정  │  │  A. 답변... │                            │
│   └─────────────┘  └─────────────┘                            │
│                                                               │
│   S1. 정보가 분산되어 있었다                                   │
│   S2. SPA로 묶었다                                             │
│                                                               │
│  ══════════ 🔄 게시판을 뒤집는다 ══════════                    │
│                                                               │
│   ═══ 뒷면 · 내가 만든 것 ═══                                  │
│                                                               │
│   $ git push                                                  │
│   → build → docker → nginx → LIVE                             │
│                                                               │
│   S3. 배포까지가 개발이다                                       │
│   S4. 결과                                                     │
└───────────────────────────────────────────────────────────────┘
```

### S3. 뒷면 — 배포까지가 개발이다 ⭐

**이 섹션이 이 프로젝트를 다른 9개와 완전히 갈라놓는 지점이다.**

**[COPY-07]**
> 학교 과제로 만든 웹은 `npm run dev`에서 끝난다. 이건 아니었다.
> 실제 학생들이 접속할 주소가 있어야 했고, 내가 자는 동안에도 떠 있어야 했다.
> **"동작한다"와 "서비스한다" 사이에 Docker와 Nginx가 있었다.**

**[NEW]** `DeployPipeline` — 이 프로젝트의 시그니처. (§4에서 상술)

**[COPY-08]** (Nginx를 왜 썼나)
> React SPA는 새로고침하면 404가 난다. `/notice/12`로 직접 들어오면 서버에 그런 파일이 없으니까.
> Nginx에서 모든 경로를 `index.html`로 넘기는 설정 한 줄이 이걸 해결했다.
> **이런 건 로컬 개발에서는 절대 안 만난다.** 배포해봐야 만난다.

- **[CODE-03]** Nginx 설정 — `try_files $uri $uri/ /index.html;` · **8~14줄** · `nginx.conf`
  포인트: **`try_files` 한 줄 하이라이트.** SPA 배포의 통과의례이자, 배포를 실제로 해본 사람만 아는 지점
- **[CODE-04]** Dockerfile (멀티 스테이지 빌드) · **10~16줄**
  포인트: build 스테이지 → nginx 스테이지로 정적 파일만 복사. 이미지 크기가 줄어드는 이유

## 4. 시그니처 인터랙션 — 「배포 파이프라인」

**[NEW]** `DeployPipeline`

뒷면 진입 직후, 화면 중앙에서 **실제 배포가 재생된다.**

```
┌──────────────────────────────────────────────────────────────┐
│  ▸ DEPLOY                                    [ 다시 배포 ↻ ] │
│                                                              │
│   ●━━━━━━━●━━━━━━━●━━━━━━━●━━━━━━━●                          │
│  commit   build   image   push    live                       │
│    ✓        ✓       ⣾       ○       ○                        │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ $ git push origin main                                 │  │
│  │ ✓ 12 files changed                                     │  │
│  │ $ npm run build                                        │  │
│  │ ✓ built in 3.42s                                       │  │
│  │ $ docker build -t ajouchong-web .                      │  │
│  │ ⣾ [3/5] COPY --from=build /app/dist /usr/share/nginx   │  │
│  │ _                                                      │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  ● 아직 배포 중                                               │
└──────────────────────────────────────────────────────────────┘
```

### 동작 명세
1. 뷰포트 진입 시 자동 시작. 5단계를 **총 4.5초**에 걸쳐 순차 진행
2. 터미널 로그가 **타이핑되듯** 한 줄씩 출력 (글자 단위 아님, **줄 단위** — 글자 단위는 너무 느리다)
3. 진행 중 단계는 스피너 `⣾⣽⣻⢿⡿⣟⣯⣷` 회전, 완료되면 `✓` 초록
4. 각 단계 완료 시 짧은 터미널 비프 (사운드 ON일 때)
5. 마지막 `live` 도달 시:
   - 하단 상태가 `● 배포 완료 · LIVE` 로 바뀌고 초록 맥동 시작
   - **화면 상단 헤더의 `● 실제 배포됨` 뱃지가 한 번 밝게 점멸** ← 앞면과 뒷면을 잇는 디테일
   - 파이프라인 트랙 전체가 초록으로 채워짐
6. `↻ 다시 배포` 로 재생 가능
7. 각 단계 노드를 클릭하면 그 단계의 설명이 하단에 고정 표시 (자동 재생 일시정지)

### 단계별 설명 [COPY]
| 단계 | 설명 |
|---|---|
| commit | "코드를 올린다. 여기까지는 누구나 한다." |
| build | "Vite가 정적 파일을 만든다. 여기서 끝내면 내 컴퓨터에서만 돈다." |
| image | "Docker 멀티 스테이지 — 빌드 결과물만 Nginx 이미지에 복사한다. 무거운 node_modules는 안 딸려간다." |
| push | "이미지를 서버로. 서버 환경이 뭐든 컨테이너 안은 항상 같다." |
