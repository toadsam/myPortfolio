# 07. 수어지구 — 「소리 없는 갤러리」

> 수어 아바타 학습·표현 서비스 · Spring Boot / Firebase / React / TypeScript / 3D Avatar
> 테마: `primary #7eb8ff` / `secondary #60a5fa` / `bg #060d18` / `accent #bfdbfe`

---

## 0. 한 줄 컨셉

**"소리를 끄고 들어오는 방."**

10개 프로젝트 중 **유일하게 사운드가 기본 OFF**다. 그리고 그게 의도라는 걸 화면이 먼저 말한다.

다른 프로젝트가 정보 밀도와 속도로 승부한다면, 이 방은 **여백과 정적**으로 간다.
빽빽한 대시보드도, 깜빡이는 로그도 없다. 넓은 여백 가운데 손동작 하나가 천천히 재생된다.

**소리가 없어도 전달된다** — 이게 수어의 본질이고, 이 화면이 증명해야 하는 것이다.

## 1. 아트 디렉션

| 항목 | 값 |
|---|---|
| 배경 | `#060d18` 깊은 남색. 그라디언트도 격자도 노이즈도 **없음**. 완전히 평평하게 |
| 주색 | `#7eb8ff` 연한 블루 |
| 손 색 | `#bfdbfe` 라인 아트. 채워진 손이 아니라 **선으로 그린 손** (2px stroke) |
| 타이포 | 본문 `leading-9`, 글자 크기 **한 단계 크게** (17px). 여백이 많으니 글씨도 여유 있게 |
| 여백 | **다른 프로젝트의 2배.** 섹션 간 `py-32`, 요소 간 `gap-10` |
| 모서리 | `rounded-2xl`, 보더는 `rgba(126,184,255,0.14)` 아주 옅게 |
| 모션 톤 | **아주 느리고 부드럽게.** duration 0.8~1.4s, `ease: [0.4, 0, 0.2, 1]`. 급한 동작 금지 |
| 사운드 | **기본 OFF.** SoundToggle은 있되 초기값 off + 그 옆에 안내 문구 |

### 사운드 정책 — 이 프로젝트만의 규칙

```
🔇  이 방은 소리 없이 설계되었습니다        [ 소리 켜기 ]
```
- 헤더에 위 문구를 상시 표시
- 켜면 아주 조용한 앰비언트(패드)만 나옴. 효과음은 **없음**
- **소리를 켜도 정보가 늘어나지 않는다.** 그게 이 방의 주장이다

## 2. 진입 연출 (0 → 2.6초)

**무음. 손이 인사한다.**

```
0.0s  완전히 검은 화면. 소리 없음.
0.5s  화면 중앙에 손 실루엣이 선으로 그려짐 (SVG path 드로잉, stroke-dashoffset)
1.2s  손이 인사 동작을 한 번 (좌우로 부드럽게, 0.8s)
2.0s  손이 화면 아래로 천천히 내려가며 페이드
2.2s  타이틀이 조용히 페이드인 (움직임 없이, opacity만)
        수어지구
        소리 없이도 전달된다
2.6s  스크롤 활성화
```

- **다른 프로젝트 진입 연출은 전부 소리가 있다. 여기만 없다.** 그 대비가 이 방의 인상을 만든다
- 진입에 `DecodeText`, 스크램블, 플래시 **전부 금지**
- **스킵**: 클릭/키/스크롤 → 2.2s 상태로
- `reduced-motion` → 손 드로잉 생략, 정지된 손 이미지 → 페이드

### S1. 배우고 싶어도 배울 곳이 없었다 — 문제

**[COPY-03]**
> 수어를 배우려고 찾아보면 나오는 건 대부분 사진이었다.
> 그런데 **수어는 정지 이미지로 배울 수 없다.** 손 모양만이 아니라 움직임과 방향과 속도가 전부 의미다.
> 영상은 있지만, 원하는 단어 하나를 찾아서 반복 재생하기가 불편했다.

**[COPY-04]** (강조 블록)
> 필요한 건 **동작을 보고, 의미를 맞혀보고, 틀리면 다시 보는 반복 루프**였다.
> 사진 사전도 영상 강의도 그 루프를 만들어주지 못했다.

**[NEW]** `StillVsMotion` — 문제를 한 화면으로 보여주는 비교.
```
┌──────────────────┐        ┌──────────────────┐
│                  │        │                  │
│    ✋ (정지)      │   vs   │   ✋ (움직임)     │
│                  │        │                  │
│  "이게 무슨 뜻?"  │        │   "아, 이거구나"  │
└──────────────────┘        └──────────────────┘
   사진 사전                    동작 재생
```
좌측은 정지된 손 SVG, 우측은 **같은 손이 실제로 움직인다.**
말로 설명하지 않고 나란히 놓기만 해도 차이가 즉시 보인다. **이 프로젝트에서 가장 설득력 있는 한 장면.**

## 4. 시그니처 인터랙션 — 「손 아바타 재생기」

**[NEW]** `HandPlayer` (기존 `SignLanguageDemo.tsx` 를 이 컨셉으로 재작성)

```
┌─────────────────────────────────────────────────┐
│                                                 │
│                                                 │
│                   ✋                             │
│              (SVG 손, 선으로)                    │
│                                                 │
│                                                 │
│   ────────●──────────────────────                │
│   0:00                        0:02              │
│                                                 │
│   [ 안녕하세요 ▾ ]        [ ▶ 재생 ] [ 0.5× ]   │
│                                                 │
│   또는 직접 입력 ▸  [                    ]      │
└─────────────────────────────────────────────────┘
```

### 동작 명세
1. **SVG 손 하나**를 키포즈 사이로 보간하며 움직인다.
   - 3D 모델 쓰지 않는다. 번들이 무겁고, 로딩이 길고, 이 방의 조용한 톤과 안 맞는다
   - 손가락 5개 + 손바닥을 `<path>` 로 구성. 각 키포즈는 path의 `d` 값 세트
   - `framer-motion` 의 path morphing 또는 관절 각도 기반 회전 중 **관절 각도 방식 권장** (path morph는 점 개수가 같아야 해서 까다롭다)
   - 손 전체의 위치/회전 + 손가락 굽힘 각도만으로 충분히 "동작"으로 읽힌다
2. **단어 선택**: 드롭다운에 5~6개 단어. `안녕하세요` `감사합니다` `괜찮아요` `아주대학교` `수어` `반갑습니다`
3. **재생 컨트롤**: `▶ 재생` / `0.5× 느리게` — 느린 재생은 실제 수어 학습에서 필수 기능이다. 이게 있는 것만으로 도메인 이해도가 보인다
4. **타임라인 스크럽**: 관람객이 재생바를 직접 드래그해서 동작을 프레임 단위로 볼 수 있다. ← **관람 포인트**
5. **직접 입력**: 텍스트 입력 → 단어 사전에 있으면 해당 시퀀스 재생, 없으면
   `사전에 없는 단어입니다. 지원 단어: 안녕하세요, 감사합니다, ...` 안내
   (없는 단어에 아무 동작이나 재생하면 그건 거짓말이다. **반드시 없다고 말할 것**)
6. **소리 없음.** 재생 중에도 어떤 효과음도 나지 않는다. 이 방의 원칙

### 왜 이게 시그니처인가
"수어 아바타를 만들었습니다"는 말로는 아무것도 전달되지 않는다.
**손이 실제로 움직이는 걸 보는 순간** 이 프로젝트가 무엇인지 즉시 이해된다.
그리고 그게 정확히 이 프로젝트가 해결하려던 문제(정지 이미지로는 안 된다)와 같다.

### 정확성 주의 ⚠️
- 실제 한국수어 동작을 **부정확하게 흉내내면 안 된다.**
- SVG 손은 **"개념적 재현"**임을 명시: 재생기 하단에 상시 캡션
  `// 실제 서비스의 3D 아바타를 단순화한 개념 재현입니다`
- 정확한 수어 동작을 주장하지 않는다. 그건 당사자 감수 없이 할 수 없는 주장이다

### 성능
- SVG 애니메이션만 사용. 캔버스/WebGL 불필요
- 키포즈 데이터는 단어당 4~8프레임이면 충분
- 뷰포트 이탈 시 재생 정지

### 모바일
- 손 크기 축소, 컨트롤은 세로 스택
- 타임라인 스크럽은 터치 드래그 지원 필수
