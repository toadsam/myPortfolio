# 08. 아주대모험 — 「오락실 캐비닛」

> 아주대 캠퍼스 배경 Phaser 3 기반 2D 캐주얼 게임 · TypeScript / Phaser 3 / Vite
> 테마: `primary #a3e635` / `secondary #84cc16` / `bg #0a0f04` / `accent #bef264`

---

## 0. 한 줄 컨셉

**"오락실에 코인을 넣는다."**

이 프로젝트는 **웹 게임**이다. 그러면 관람객도 게임을 해야 한다. 설명을 읽는 게 아니라.

화면 전체가 오락실 캐비닛이다. CRT 스캔라인, 8비트 폰트, `INSERT COIN`, `HIGH SCORE`.
그리고 화면 한가운데에 **실제로 플레이 가능한 미니 러너**가 있다.

이 방의 성공 기준은 하나다: **관람객이 최소 한 판은 플레이한다.**

## 1. 아트 디렉션

| 항목 | 값 |
|---|---|
| 배경 | `#0a0f04` + **CRT 스캔라인** (`repeating-linear-gradient(0deg, rgba(0,0,0,0.28) 0 1px, transparent 1px 3px)`) |
| 비네트 | 화면 가장자리 어둡게 (`radial-gradient(transparent 55%, rgba(0,0,0,0.6))`) — 브라운관 곡률 흉내 |
| 주색 | `#a3e635` 라임 — 인광(phosphor) 초록 |
| 보조 | `#bef264` / 경고 `#f87171` / 하이스코어 `#fbbf24` |
| 타이포 | **전면 픽셀/모노.** 웹폰트 추가 없이 `font-mono` + `letter-spacing 0.05em` + `text-transform: uppercase` 로 8비트 느낌 |
| 모서리 | `rounded-none` — **각지게. 이 프로젝트만 둥근 모서리 금지.** 픽셀에 라운드는 없다 |
| 이미지 | 모든 이미지에 `image-rendering: pixelated` |
| 모션 톤 | **딱딱 끊기게.** `ease: steps(4)` 또는 `linear`. 부드러운 이징 금지. 스프링 절대 금지 |
| 사운드 | variant `arcade`. 8비트 사각파. 코인 삽입 / 점프 / 아이템 / 게임오버 / 하이스코어 |

### 이 프로젝트만의 장치
- **CRT 깜빡임**: 아주 미세한 밝기 흔들림 (`opacity 0.98 ↔ 1.0`, 4초 주기). 과하면 눈이 아프다
- **글리치**: 섹션 전환 시 0.12초 짧은 RGB 분리 + 수평 밀림. **드물게, 짧게.**
- ⚠️ **광과민성 주의**: 초당 3회 이상 깜빡임 금지. 글리치는 0.15초 이내, 연속 2회 이상 금지

## 2. 진입 연출 (0 → 2.8초)

**부팅 → 크레딧 → 어트랙트 모드.**

```
0.0s  검은 화면. CRT 켜지는 소리(짧은 고주파) + 화면 중앙에 가로선 하나가
      위아래로 확 펼쳐짐 (브라운관 켜지는 연출, 0.25s)
0.4s  스캔라인 나타남
0.6s  좌상단부터 부팅 텍스트 출력 (줄 단위)
        AJOU ADVENTURE
        PHASER 3 / TYPESCRIPT / VITE
        LOADING........ OK
1.4s  화면 중앙에 큼직하게
        ┌────────────────────┐
        │   INSERT COIN      │  ← 0.6초 주기로 깜빡임
        │   ▶ PRESS START    │
        └────────────────────┘
      우상단에  HIGH SCORE  00000  (localStorage 값이 있으면 그 값)
2.0s  자동으로 코인 삽입 애니메이션 (관람객이 안 눌러도 진행)
      코인 사운드 + 화면 하단에 CREDIT 01
2.8s  스크롤 활성화 + 미니 게임 준비 완료 상태
```

- **관람객이 `PRESS START` 를 직접 누르면** 즉시 게임 시작 (연출 스킵)
- `reduced-motion` → CRT 켜짐/깜빡임 제거, 텍스트 즉시 표시
- ⚠️ `INSERT COIN` 깜빡임은 0.6초 주기 = 초당 1.67회. 안전 범위

## 3. 섹션 구성

**레이아웃 대원칙**: 이 프로젝트만 **스크롤이 아니라 「스테이지 선택」** 이다.
세로 스크롤도 되지만, 상단에 스테이지 탭이 있어서 **점프 이동**이 주 동선이다.

```
┌═══════════════════════════════════════════════════════════════┐
│ ◂ EXIT   AJOU ADVENTURE          HIGH SCORE 01240   ♪ ON      │
├═══════════════════════════════════════════════════════════════┤
│  [ 1P PLAY ] [ STAGE 1 ] [ STAGE 2 ] [ STAGE 3 ] [ STAFF ]   │
│      ▲                                                        │
│   현재 선택                                                    │
├═══════════════════════════════════════════════════════════════┤
│                                                               │
│   ┌───────────────────────────────────────────────────┐       │
│   │                                                   │       │
│   │      █▀▀▄   ← 플레이어                            │       │
│   │  ────────────  ▄▄▄  ────────  ▄▄▄                 │       │
│   │                                                   │       │
│   │   SCORE 0240        ← 실제 플레이 영역             │       │
│   └───────────────────────────────────────────────────┘       │
│                                                               │
│         ← → 이동    SPACE 점프    (모바일: 탭)                 │
│                                                               │
└═══════════════════════════════════════════════════════════════┘
```

| 탭 | 내용 |
|---|---|
| **1P PLAY** | 시그니처 미니 러너. 기본 선택 |
| **STAGE 1** | 왜 만들었나 — 문제/기획 |
| **STAGE 2** | 게임 루프 설계 — Phaser 구조, 오브젝트 풀링 |
| **STAGE 3** | 만든 것 — 기능/최적화/결과 |
| **STAFF** | 회고 · 배운 점 (게임 엔딩 크레딧 형식) |

> 탭 전환 시 0.12초 글리치 + 화면이 좌우로 슬라이드. 스크롤 위치는 각 탭마다 독립 유지.

**[COPY-03]**

### STAGE 2 — 게임 루프 설계 ⭐

**이 스테이지가 이 프로젝트의 기술적 알맹이다.** 게임은 "만들었다"보다 "어떻게 돌게 했나"가 중요하다.

**[COPY-05]** (핵심 문제)
> 자동 스크롤 게임은 발판과 장애물을 계속 만들어낸다.
> 처음 만들었을 때 1분 정도 플레이하면 프레임이 눈에 띄게 떨어졌다.
> 원인은 단순했다. **화면 밖으로 나간 오브젝트를 아무도 치우지 않았다.**

```
┌───────────────────────────────────────────────────────┐
│  ▸ OBJECT LIFECYCLE                                   │
│                                                       │
│  BEFORE                     AFTER                     │
│  ──────                     ─────                     │
│  생성 →  →  →  →  →  ∞      생성 → 사용 → 회수 ┐      │
│  (계속 쌓임)                    ▲              │      │
│                                 └──────────────┘      │
│  오브젝트 수                 오브젝트 수               │
│  ▁▂▃▄▅▆▇█ 계속 증가          ▃▃▃▃▃▃▃▃ 일정 유지       │
└───────────────────────────────────────────────────────┘
```

**[NEW]** `ObjectPoolDemo` — 관람객이 직접 확인하는 데모.
```
[ 풀링 OFF ]  [ 풀링 ON ]   ← 토글

활성 오브젝트  ████████████████████  128   ← OFF일 때 계속 증가
활성 오브젝트  ██████  24                  ← ON일 때 일정
```
- 토글을 끄면 카운터가 계속 올라가고, 켜면 일정하게 유지되는 걸 **숫자로 보여준다**
- 실제 프레임 드랍을 재현하진 않는다 (그건 관람객 브라우저를 괴롭히는 짓). **카운터만으로 충분**

- **[CODE-01]** 게임 루프 (`update`) · **14~20줄** · Phaser `Scene.update`
  포인트: 매 프레임 하는 일 — 스크롤, 생성 판정, 충돌, 정리
- **[CODE-02]** 오브젝트 생성/회수 (풀링 또는 destroy) · **12~18줄**
  포인트: **화면 밖 판정 + 회수** 부분 하이라이트. 이게 [COPY-05]의 답
- **[CODE-03]** 점프 메커니즘 · **10~14줄**
  포인트: 착지 판정, 중력, 점프 입력 버퍼가 있으면 그것도

**[COPY-06]** (배운 것 — 여기가 면접 답변)
> 게임 루프는 매 프레임 도는 코드다. 웹에서 60fps면 초당 60번이다.
> **여기에 들어가는 한 줄은 다른 곳의 한 줄과 무게가 다르다**는 걸 이 프로젝트에서 처음 체감했다.
> 이후로는 반복 실행되는 코드에서 "이거 매번 해야 하나?"를 먼저 묻게 됐다.

## 4. 시그니처 인터랙션 — 「실제 플레이 가능한 미니 러너」

**[NEW]** `MiniRunner` (기존 `AjouAdventureDemo.tsx` 를 실제 플레이 가능하게 확장)

### 사양
```
┌──────────────────────────────────────────────────┐
│  SCORE 0240          HIGH 01240        ♥♥♡       │
│                                                  │
│                                                  │
│      █▀▀▄                                        │
│      █▄▄█        ▲              ●                │
│  ▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄  ▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄        │
│                                                  │
│              ← → 이동   SPACE 점프                │
└──────────────────────────────────────────────────┘
```

- **엔진**: Phaser 아님. **순수 `<canvas>` + `requestAnimationFrame`.**
  (Phaser를 번들에 넣으면 이 포트폴리오 전체가 무거워진다. 미니 버전은 200줄이면 충분)
- **게임플레이**: 좌우 자동 스크롤 러너. 발판을 밟고, 장애물을 피하고, 아이템을 먹는다
- **조작**: `←` `→` 이동 / `Space` 또는 `↑` 점프 (2단 점프 지원 — 원작 기능이니까)
- **모바일**: 화면 좌/우 절반 탭 = 이동, 위로 스와이프 = 점프. 또는 화면 하단 가상 버튼 3개
- **목숨 3개**. 다 잃으면 `GAME OVER` → 점수 표시 → `PRESS START`
- **하이스코어**: `localStorage` 에 저장. **원작이 실제로 쓴 기능을 여기서도 똑같이 쓴다** ← 좋은 디테일
- **캠퍼스 요소**: 발판에 건물 이름 라벨 (`팔달관`, `중앙도서관`). 아주대 사람에게만 터지는 디테일
- **길이**: 무한 러너. 난이도는 점수에 따라 아주 완만하게 상승

### 조작 안내 (필수)
게임 영역 하단에 **항상** 조작키를 표시한다. 오락실 캐비닛의 조작 안내 스티커처럼.
관람객이 뭘 눌러야 하는지 모르면 플레이율이 0이 된다.

### 키보드 캡처 주의 ⚠️
- 게임 캔버스에 **포커스가 있을 때만** 방향키/스페이스를 가로챈다
- 포커스 없을 때 스페이스를 먹으면 **페이지 스크롤이 안 되는 최악의 버그**가 된다
- 캔버스 클릭 → 포커스 획득 → 테두리가 라임색으로 빛남 (포커스 상태 시각화)
- `Esc` 또는 캔버스 밖 클릭 → 포커스 해제
- 게임 영역에 안내: `클릭해서 조작 시작`

### 성능
- 뷰포트 밖 / 다른 탭 선택 시 `cancelAnimationFrame` 으로 **완전 정지**
- 오브젝트 풀링을 **실제로 구현**한다. STAGE 2에서 풀링 얘기를 해놓고 데모가 풀링을 안 쓰면 앞뒤가 안 맞는다
- 캔버스 해상도는 논리 크기 고정(예: 640×240) + CSS로 확대. `imageSmoothingEnabled = false`

### 대체 경로
게임이 로드 실패하거나 `reduced-motion` 이면:
- 정적 스크린샷 `[IMG-01]` + `원본 게임 플레이하기 ↗` 링크로 대체
- **절대 빈 화면 금지**
